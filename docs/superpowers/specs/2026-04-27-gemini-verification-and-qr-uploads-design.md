# Спецификация: Проверка развернутой части через Gemini, QR-загрузка и контроль черновиков

## 1. Обзор (Overview)
Данное обновление вводит полноценную проверку заданий развернутой части (и выборочную проверку черновиков тестовой части) с использованием нейросети Gemini Vision. Для удобства загрузки решений с телефона реализован бесшовный механизм через QR-коды.

## 2. Архитектура и База данных
### Новые поля в моделях:
*   **User (Ученик)**:
    *   `draft_check_probability` (IntegerField, от 0 до 100) — Вероятность (в процентах), с которой система запросит фото черновика для тестовой части. Редактируется репетитором в карточке ученика.
*   **Submission (Попытка решения)**:
    *   `upload_token` (UUID) — Уникальный одноразовый токен для загрузки фото через QR-код.
    *   `requires_draft` (BooleanField) — Флаг, указывающий, что для этой задачи система потребовала загрузить черновик.
    *   `primary_score` (IntegerField) — Первичный балл за задачу (от 0 до `exam_points`).
    *   *Уже существуют, но будут задействованы:* `image_url`, `ai_feedback`, `recognized_text`.

## 3. Пользовательский путь (User Flow)

### 3.1. Бесшовная загрузка через QR-код (Десктоп ↔ Телефон)
1.  Ученик решает вариант на ПК. Открывает задачу:
    *   Если это **Развернутая часть** (`exam_points > 1`): вместо текстового поля выводится блок "Загрузите решение".
    *   Если это **Тестовая часть** (`exam_points == 1`), и сработал рандом `draft_check_probability`: выводится текстовое поле ответа + обязательный блок "Загрузите фото черновика".
2.  В блоке загрузки генерируется **QR-код**, в котором зашита ссылка вида: `https://domain.com/upload/<upload_token>/`.
3.  Ученик сканирует QR-код телефоном. Открывается минималистичная мобильная страница с кнопкой "Сделать фото / Выбрать из галереи" (без необходимости вводить логин/пароль, безопасность обеспечивает длинный UUID-токен).
4.  При успешной загрузке фото с телефона, десктопная версия (которая опрашивает сервер раз в 3 секунды) автоматически обновляет интерфейс: прячет QR-код, показывает миниатюру фото и кнопку "Проверить через ИИ".

### 3.2. Проверка через Gemini
1.  По нажатию "Проверить" сервер отправляет в Gemini:
    *   Фото решения (base64).
    *   Условие задачи.
    *   Правильный ответ / эталонное решение (из базы).
    *   Максимальный первичный балл (`task.exam_points`).
2.  Промпт требует от Gemini вернуть строго JSON:
    ```json
    {
      "primary_score": 2,
      "feedback": "Вы правильно применили формулу дискриминанта, но ошиблись в вычислении корней на последнем шаге. Из-за вычислительной ошибки снимается 1 балл."
    }
    ```
3.  Сервер сохраняет баллы и фидбек в `Submission` и выводит результат ученику.

### 3.3. Перевод баллов (Первичные во Вторичные)
1.  В коде создается конфигурационный словарь со шкалой перевода ЕГЭ Профиль (например, 32 первичных = 100 вторичных).
2.  При завершении варианта система суммирует все `primary_score` ученика.
3.  На странице "Резюме варианта" (Summary) выводится: "Первичный балл: 15/32" и "Тестовый (вторичный) балл: 70/100".
4.  Если задача решалась вне варианта (в Тренажере), вторичный балл (и XP) высчитывается пропорционально весу задания.

## 4. Панель Репетитора (Управление)
*   В форме "Контакты и заметки" (где мы добавили телефоны родителей) появится ползунок/ввод: **"Частота запроса черновиков (0-100%)"**.
*   Репетитор может поставить 100%, если подозревает ученика в списывании, или 0%, если доверяет.

## 5. Безопасность и Ограничения
*   Токен `upload_token` живет временно (или привязан строго к конкретному нерешенному `Submission`).
*   Как только фото прикреплено, токен аннулируется, чтобы по ссылке нельзя было загрузить другое фото позже.
*   Ограничение на размер загружаемого фото: до 5-10 МБ, сжатие на клиенте (в браузере телефона) перед отправкой.
