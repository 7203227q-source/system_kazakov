# Дизайн: дашборд репетитора — предметная фильтрация правой панели + недельный график «правильно/неправильно»

Дата: 2026-05-14  
Затрагиваемые страницы: `tutor_dashboard` (дашборд репетитора)  

## Контекст

В дашборде репетитора уже есть:
- переключатель предмета (чипы) для выбранного ученика;
- график «Мастерство и прогноз» (Chart.js, `DailySnapshot`) по выбранному предмету;
- блок «Решаемость по номерам» по выбранному предмету;
- список вариантов ученика («Текущие», «Решённые») **без** предметной фильтрации (исторически сделано специально).

Нужно:
1) Добавить под графиком мастерства/прогноза ещё один график: **количество правильно и неправильно решённых задач по дням за последнюю неделю** (для выбранного ученика).
2) Исправить предметную сегментацию на дашборде репетитора: при выборе «Физика» не показывать задания/варианты по математике (и наоборот) **в правой панели**.

Важно: пользователь подтвердил, что предметная фильтрация должна влиять **только на правую часть** (детали выбранного ученика), а список учеников слева остаётся общим.

## Цели

### 1) Недельная диаграмма «правильно/неправильно»
- Для выбранного ученика показать столбчатую диаграмму за последние 7 дней (включая сегодня):
  - красный столбик: сколько задач решено неправильно;
  - синий столбик: сколько задач решено правильно.
- Диаграмма должна быть предметной: данные берутся **только по выбранному предмету** (математика/физика).
- Источник данных: **все решения ученика (Submission)** по выбранному предмету (варианты, повторение/тренажёр, загрузки фото и т.д.).
- Подсчёт: **уникальные задачи в день** — если одну и ту же задачу решали несколько раз за день, учитываем **последнюю попытку** в этот день и по ней определяем «правильно/неправильно».
- Не учитывать записи без финального вердикта (`is_correct is None`).

### 2) Предметная фильтрация правой панели (variants + «рекомендации по повторению»)
- При выборе предмета в дашборде репетитора:
  - список вариантов («Текущие»/«Решённые») должен показывать **только варианты выбранного предмета**;
  - любая статистика/аналитика в правой панели должна соответствовать выбранному предмету (сейчас график и «решаемость по номерам» уже предметные).
- Список учеников слева не фильтруется (как выбрано пользователем).

Примечание про «рекомендации по повторению»: на текущем UI дашборда репетитора нет отдельного блока рекомендаций SRS; предметная сегментация в рамках этой задачи означает, что **все показанные на правой панели данные/списки**, которые основаны на задачах/решениях, должны быть ограничены выбранным предметом. (Если позже появится отдельный блок SRS-рекомендаций в правой панели — он должен использовать тот же `subject_id`.)

## Не цели (не делаем в рамках задачи)
- Не меняем структуру/логику списка учеников слева (XP/прогноз/индикатор активности остаются «общими» по всем предметам).
- Не добавляем режим «Все предметы» для правой панели (можно обсудить отдельно).
- Не вводим отдельный API-эндпоинт для графика (всё считается на сервере внутри `tutor_dashboard`).
- Не создаём отдельные таблицы агрегаций по дням (данные считаются на лету за 7 дней).

## UX / Размещение на странице

На `tutor_dashboard.html` в блоке «Прогноз и Аналитика» уже есть:
- карточки по предметам (мелкая сводка),
- график мастерства/прогноза (line chart),
- «Решаемость по номерам».

Новый график добавляем **сразу под** графиком мастерства/прогноза:
- заголовок: «За последнюю неделю: правильно / неправильно»
- `<canvas id="studentWeeklySolvedChart">`
- если данных нет — показываем текст «Нет данных за последнюю неделю».

## Технический дизайн

### Параметры/контекст

Используем существующие GET-параметры:
- `student_id` — выбранный ученик
- `subject_id` — выбранный предмет (уже есть)
- `range` — диапазон основного графика (30/90/365)

Добавляем в context (только для `selected_student`):
- `weekly_solved_chart_data`: JSON вида:
  ```json
  {
    "labels": ["Пн 06.05", "Вт 07.05", "..."],
    "correct": [3, 1, 0, 2, 0, 5, 4],
    "incorrect": [1, 0, 2, 0, 1, 0, 3]
  }
  ```

### Предметная фильтрация вариантов (Assignments) в правой панели

Сейчас `assignments = Assignment.objects.filter(tutor=..., student=..., is_draft=False, is_deleted=False)` без предметного фильтра.

Новая логика:
- если `chart_subject_id` задан:
  - предпочитаем фильтрацию по `assignment.exam_format.subject_id == chart_subject_id` (быстро, если заполнено);
  - для вариантов без `exam_format` используем fallback: фильтрация по задачам `tasks__topic__subject_id == chart_subject_id` (через `distinct()`).

Результат: `active_assignments` и `completed_assignments` будут собраны из уже отфильтрованного набора.

### Расчёт недельной статистики «правильно/неправильно»

Период:
- `today = timezone.localdate()`
- `start_date = today - timedelta(days=6)` (7 дней включая сегодня)

Источник:
- `Submission.objects.filter(student=selected_student, created_at__date__gte=start_date, created_at__date__lte=today, is_correct__isnull=False)`
- если `chart_subject_id` задан: добавляем `filter(task__topic__subject_id=chart_subject_id)`

Подсчёт «уникальные задачи в день, по последней попытке»:
- получаем выборку, отсортированную по `created_at` (возрастающе);
- строим `last_by_day_task[(date, task_id)] = is_correct` — при проходе по отсортированному списку последняя запись в рамках дня перезапишет предыдущую;
- затем агрегируем по дням:
  - если `is_correct == True` → `correct[date] += 1`
  - если `is_correct == False` → `incorrect[date] += 1`
- формируем массивы строго по всем 7 дням (даже если 0).

Производительность:
- выборка ограничена последней неделей и одним учеником, поэтому допускается Python-агрегация.

### Chart.js конфигурация (bar chart)

- `type: 'bar'`
- `datasets`:
  - Correct: label `Правильно`, backgroundColor `#2563EB` (синий)
  - Incorrect: label `Неправильно`, backgroundColor `#EF4444` (красный)
- `options`:
  - `responsive: true`
  - `maintainAspectRatio: false`
  - `scales.y.beginAtZero = true`
  - legend: `position: 'bottom'`

## Тестирование

Добавляем регрессионные тесты уровня `TestCase`:

1) **Предметная фильтрация вариантов в правой панели**
- Создать у ученика 2 варианта: один по математике, другой по физике.
- Открыть `tutor_dashboard?student_id=...&subject_id=<math>`:
  - в HTML должны присутствовать только элементы/заголовки math-варианта;
  - physics-вариант отсутствует.
- Аналогично для physics subject_id.

2) **Недельный график: корректность подсчёта**
- Создать 2 задачи одного предмета и сабмишены в разные даты последней недели.
- В один день сделать 2 сабмишена по одной задаче: сначала `is_correct=False`, потом `True` — в графике день должен учесть её как `True` (последняя попытка).
- Проверить, что в контексте/HTML присутствует `studentWeeklySolvedChart` и `weekly_solved_chart_data` содержит ожидаемые массивы.

## Критерии приёмки

- В дашборде репетитора под графиком мастерства/прогноза отображается недельная столбчатая диаграмма «правильно/неправильно» для выбранного ученика.
- Переключение предмета (Математика/Физика) влияет на:
  - данные недельного графика,
  - список вариантов в правой панели (показываются только варианты выбранного предмета),
  - остальная предметная аналитика остаётся консистентной.
- Список учеников слева не меняется при переключении предмета.
