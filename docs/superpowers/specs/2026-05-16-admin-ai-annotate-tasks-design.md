# Дизайн: ИИ‑оценка сложности задач из админ‑панели

Дата: 2026-05-16

## Контекст

В системе есть ИИ‑разметка задач (сложность и теги), реализованная management‑командой:
`python manage.py ai_annotate_tasks`.

В модели `Task` хранятся поля:
- `ai_difficulty_raw` (1..100)
- `ai_difficulty_exam_percentile`, `ai_difficulty_type_percentile`
- `ai_annotated_at`, `ai_annotation_version`
- `ai_tags`

Сейчас разметка запускается только через CLI, поэтому в проде/админке “не видно как это работает”.

## Цель

Добавить запуск разметки **через Django admin**:
- работать **по текущему фильтру** (queryset списка в админке);
- запускать **порциями по 25 задач**, чтобы админка не зависала слишком долго;
- использовать ключ OpenRouter только из **ENV `OPENROUTER_API_KEY`**;
- по умолчанию размечать только **новые/устаревшие по версии** задачи (как сейчас в команде, без `--force`).

## Пользовательский сценарий

1) Админ/контент‑менеджер заходит в Django admin → `Task`.
2) Выставляет фильтры (exam_format / task_type / поиск и т.п.).
3) В action выбирает: **«ИИ: размечать сложность (по фильтру, 25 шт.)»**.
4) Система размечает первые 25 задач из текущего queryset, которые “нуждаются в разметке”.
5) В админке показывается `messages.success/error`:
   - сколько задач найдено по фильтру;
   - сколько действительно размечено;
   - (опционально) сколько пропущено, т.к. уже размечены актуальной версией.

## Правила отбора задач

Action работает по queryset, заданному текущими фильтрами в админке, но дополнительно применяет “нуждается в разметке”:

- если `ai_difficulty_raw IS NULL` **или**
- `ai_annotation_version IS NULL` **или**
- `ai_annotation_version != ANNOTATION_VERSION`

Это соответствует текущему поведению `ai_annotate_tasks` без флага `--force`.

## Как технически реализуем

### Вариант A (рекомендованный): reuse существующего кода без HTTP‑клиента в admin

Вынести “разметить один Task” (построить prompt → вызвать OpenRouter → распарсить → сохранить поля/теги) в отдельную функцию, которую смогут использовать:
- management‑команда
- admin action

Слой admin action должен:
- собрать queryset по фильтру;
- применить доп. фильтр “нуждается в разметке”;
- взять первые 25 задач;
- прогнать цикл разметки;
- после — вызвать пересчёт процентилей по затронутым `exam_format`.

### Обработка ошибок

- Если `OPENROUTER_API_KEY` не установлен — показываем `messages.error` и ничего не делаем.
- Если OpenRouter вернул ошибку по одной задаче:
  - прекращаем action и показываем ошибку (чтобы админ сразу увидел проблему),
  - либо (альтернатива) продолжаем и накапливаем список ошибок (сложнее).
  Рекомендация: **останавливаемся на первой ошибке**.

### Производительность

- Порция 25 задач.
- Пауза `sleep(0.1)` можно сохранить (как в команде).
- В конце пересчитать процентили для соответствующих `exam_format_id`.

## UI в админке

В `TaskAdmin`:
- В list_display уже можно показывать `ai_difficulty_raw`, `ai_annotated_at`, `ai_annotation_version`.
- Добавить `actions = [annotate_ai_difficulty_filtered_25]`.

Action должен иметь читаемое название:
**«ИИ: разметить сложность (по текущему фильтру, 25 шт.)»**.

## Ограничения доступа

Action доступен только `is_staff` (по умолчанию для admin), дополнительно можно ограничить суперпользователями при необходимости.

## Критерии готовности

- В админке можно отфильтровать задачи и запускать разметку “порциями”.
- После запуска выбранные задачи получают `ai_difficulty_raw`, `ai_annotated_at`, `ai_annotation_version`, `ai_tags`.
- Процентили пересчитываются и появляются в `ai_difficulty_*_percentile`.
- При отсутствии `OPENROUTER_API_KEY` — понятная ошибка в админке.
