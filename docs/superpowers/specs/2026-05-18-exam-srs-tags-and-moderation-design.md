# Спека: Экзамен-ориентированное интервальное повторение (1 задача), теги/сложность, очередь модерации

Дата: 2026-05-18  
Статус: draft (готово к ревью)

## Цель

1) В режиме тренажёра выдавать **одну задачу за раз** строго **в рамках выбранного экзамена** (`ExamFormat` в профиле ученика).
2) Для задач хранить и отображать:
   - **сложность** (в т.ч. ИИ-оценку)  
   - **теги** (для поиска похожих задач и интервального повторения)
3) Проверка решения:
   - текст/код: автоматическая проверка (где возможно) / ИИ
   - фото: ИИ
4) Ручная модерация:
   - **только по запросу ученика**
   - попадает **в очередь**
   - пока заявка не решена — попытка **не влияет** на интервалы (SRS “замораживается” по этой попытке)

## Текущее состояние (в кодовой базе)

- `Task` уже содержит поля ИИ-сложности и связь M2M `ai_tags` с `TaskTag`:
  - `ai_difficulty_raw`, `ai_difficulty_exam_percentile`, `ai_difficulty_type_percentile`, `ai_tags`, `ai_annotated_at`, `ai_annotation_version`
- Есть пакетная команда `ai_annotate_tasks` и сервис `services_task_ai_annotation` для прогона по базе и пересчёта процентилей.
- Есть `SpacedRepetition` + SM-2 (`core/services.py`: `process_task_submission`, `get_due_tasks_for_student`).
- `student_practice` уже умеет режим `mode=srs` и выдаёт одну задачу (первую по `next_review_date`).
- Для развёрнутой части в SRS-режиме создаётся `Submission` для загрузки фото и ИИ-проверки.

## Решение (изменения относительно текущего)

### 1) Строго внутри экзамена (ExamFormat)

Определение “текущего экзамена” для ученика:
- берём `StudentSubjectProfile.exam_format` (активный предмет в UI уже выбирается).

Фильтрация задач для SRS:
- Считаем, что `Task` принадлежит экзамену через `Task.task_type.exam_format`.
- В режиме `mode=srs` берём записи `SpacedRepetition` только по задачам, относящимся к активному `exam_format`.

### 2) Выбор следующей задачи (одна задача)

В режиме `mode=srs`:
1) Если есть задачи “пора повторить” (`next_review_date <= today`) — выбираем из них.
2) Если таких нет — выбираем **новую задачу** (для этого пользователя в рамках этого экзамена), приоритизируя слабые теги.

Анти-зацикливание:
- исключаем задачу, если по ней есть “ожидающая модерация” (см. ниже)
- исключаем только что показанные (если появятся признаки повторного показа подряд)

### 3) Слабые теги и похожесть

Источник тегов задачи:
- на MVP используем существующие `Task.ai_tags` (M2M к `TaskTag`)
- в будущем можно добавить “ручные теги” отдельно, но в рамках этой спеки — не требуется

Слабость тега для пользователя внутри экзамена:
- считаем по истории финальных попыток (см. “Попытки и модерация”)
- базовая метрика: `weakness = 1 - correct_rate`, где `correct_rate = correct/total` (со сглаживанием)

Скоринг задачи:
- сумма слабостей тегов, входящих в задачу (опционально с весами по `TaskTag.kind`)

### 4) Попытки, проверка и модерация “в очередь”

Новая сущность: `ReviewRequest` (или `SubmissionReviewRequest`), связанная с попыткой.

Требование:
- ученик всегда может отправить решение на ручную модерацию
- при отправке:
  - создаётся заявка со статусом `queued`
  - попытка получает статус `pending_review`
  - интервалы SRS по этой попытке не обновляются до решения модератора

Минимальные статусы:
- `review_requests.status`: `queued` | `resolved`
- `attempt.status`: `final` | `pending_review`

Вердикт модератора:
- `verdict_is_correct` (boolean)
- опционально: комментарий модератора
- после `resolved`:
  - фиксируем финальный `is_correct_final`
  - обновляем `SpacedRepetition` (SM-2) по финальному результату

### 5) Сложность и теги в редакторе задачи

Существующая ИИ-разметка (batch) остаётся основным способом заполнения.

В UI редактирования задачи:
- показываем ИИ-сложность и процентили
- показываем ИИ-теги
- (опционально) добавляем кнопку “пересчитать ИИ” для одной задачи (не обязательно для MVP, если уже есть admin action/команда)

## Контракты (в терминах поведения UI)

### student_practice (mode=srs)
- всегда отдаёт одну задачу
- всегда ограничивает задачи экзаменом из текущего профиля
- если `due` пусто — отдаёт новую задачу

### submit
- сохраняет попытку
- если ученик НЕ отправил на модерацию — попытка `final`, SRS обновляется сразу
- если ученик отправил — попытка `pending_review`, SRS не меняется до решения

## Критерии приёмки

1) В `mode=srs` ученик получает задачи только из своего `exam_format`.
2) Если `due` пусто — выдаётся новая задача (не решавшаяся ранее) внутри экзамена, предпочтительно по слабым тегам.
3) Если ученик отправил на модерацию — попытка не меняет интервалы до `resolved`.
4) После вердикта модератора SRS обновляется по финальному “правильно/неправильно”.
5) Теги/сложность доступны из базы и используются для выбора “новых” задач.
