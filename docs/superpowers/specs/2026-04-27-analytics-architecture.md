# Спецификация: Архитектура аналитического модуля (ОГЭ/ЕГЭ)

## 1. Оценка текущего мастерства (Current Mastery)
Вместо статического среднего балла используется адаптивная взвешенная модель, оценивающая реальный уровень подготовки в режиме реального времени.

### 1.1. Иерархия навыков (Skill-based Assessment)
*   **Микро-навыки (skill_id)**: Общий балл формируется на основе мастерства в конкретных подтемах (например, "Тип 12: Исследование функций").
*   **Агрегация**: Итоговый балл за предмет — средневзвешенное значение мастерства по всем темам спецификации экзамена (Математика, Физика и т.д.).

### 1.2. Математическая модель расчета
*   **Экспоненциальное сглаживание (EMA)**:
    `Mastery = (Current_Score * α) + (Previous_Mastery * (1 - α))`
    *Коэффициент α (0.2 - 0.3)* позволяет системе быстро реагировать на прогресс или спад, минимизируя влияние случайных ошибок прошлых периодов.
*   **Весовые коэффициенты задач**: Каждая задача имеет базовый вес в соответствии с баллами ФИПИ.
*   **Отсутствие подсказок**: Оценка выставляется строго на основе финального ответа.

### 1.3. Динамика и стабильность
*   **Коэффициент стабильности**: Система анализирует разброс результатов. Высокая волатильность (чередование 100% и 0%) снижает общий уровень мастерства до подтверждения стабильности.
*   **Учет сложности**: Правильное решение задач повышенной сложности (вторая часть) дает нелинейный прирост к мастерству.

## 2. Прогнозирование на день экзамена (Predictive Analytics)
Прогноз — это вектор движения с учетом текущего темпа и физиологических факторов памяти.

*   **Вектор Velocity (Скорость)**: Линейная регрессия последних 15-20 сессий. Определяет ожидаемый прирост баллов к дате экзамена.
*   **Вектор Decay (Забывание)**: Интеграция с алгоритмом SM-2. Если интервальные повторения просрочены, прогнозируемый балл снижается пропорционально объему забытого материала (кривая забывания).
*   **Непрерывная калибровка (Rolling Forecast & Feedback Loop)**:
    *   *Итерационная сверка*: Ежедневное сравнение `Actual_Score(T)` с `Predicted_Score_for_T`.
    *   *Накопительная ошибка*: Вычисляется среднее отклонение за последние 7–14 дней.
    *   *Корректировка (Model Bias)*: Все будущие прогнозы автоматически умножаются на коэффициент индивидуальной обучаемости и точности системы для конкретного ученика.

## 3. Индекс доверия и Роль верификатора (Trust Score)
Механизм выявления списывания и подтверждения реальности знаний через участие доверенных лиц.

### 3.1. Режимы верификации
*   **Solo Mode**: Самостоятельная работа. Доверие к данным: `0.6`. Используется для тренировки и накопления статистики.
*   **Verified Mode (Контрольная от Репетитора)**: 
    *   *Механика (Вариант Б)*: Репетитор при создании варианта (Assignment) ставит галочку "Это контрольная работа (Verified)".
    *   *Доверие*: Оценки за этот вариант автоматически получают максимальное доверие `1.0` и являются эталоном (Benchmark) для аналитики.

### 3.2. Механика подтверждения (Validation Loop)
*   **Запрос на верификацию**: При фиксации аномального роста система сигнализирует репетитору о необходимости назначить "Verified" вариант.
*   **Анализ разрыва (Gap Analysis)**: Постоянное сравнение `Verified_Performance` и `Solo_Performance`. Значительный разрыв снижает "Индекс доверия" ученика.

### 3.3. Анализ временных аномалий
*   *Механика учета времени (Вариант Б)*: Серверная дельта. Система фиксирует время выдачи/открытия варианта и время его сдачи (или отправки отдельных ответов). Среднее время на задачу высчитывается на стороне сервера.
*   **Бенчмаркинг таймингов**: Система хранит `Median_Time` для каждого типа задач, полученное исключительно в Verified-сессиях.
*   **Триггер аномалии**: Если `Solo_Time < 0.4 * Median_Time`, задача помечается как `is_anomaly`.
*   **Блокировка прогноза**: При накоплении критического числа аномалий рост прогноза замораживается до прохождения контрольного рубежа в верифицированном режиме.

## 4. Схема данных для БД (Модели Django)
*Все расчеты проводятся на стороне бэкенда асинхронно или при генерации дашбордов.*

*   **TaskLog (Submissions / Analytics)**: `id`, `user_id`, `task_id`, `time_spent`, `score`, `is_verified` (наследуется от Assignment), `verifier_role`, `is_anomaly`
*   **DailySnapshot**: `user_id`, `subject_id`, `date`, `current_mastery`, `predicted_exam_score`, `gap_between_solo_and_verified`, `rolling_forecast_error`
*   **UserCalibration (на уровне StudentSubjectProfile)**: `avg_model_error`, `trust_factor`, `last_verified_date`, `learning_velocity`
