# ОГЭ математика: шкала баллов/оценок, геометрия и отображение в прогнозе/мастерстве

## Контекст
Сейчас аналитика (`DailySnapshot.current_mastery`, `DailySnapshot.predicted_exam_score`) ведётся в шкале **0–100** и частично предполагает ЕГЭ-подобную модель. При этом разные экзамены имеют:
- разную максимальную первичную сумму;
- разные правила начисления за задания (в том числе задания проверяемые экспертом);
- разный перевод первичных баллов в итоговую оценку/результат.

Для **ОГЭ математики**:
- максимальный первичный балл = **31**;
- перевод в оценку по 5-балльной шкале имеет пороги и дополнительное условие: для оценки ≥3 нужно набрать ≥2 балла по геометрии.

Нужно «настроить» правила экзамена и использовать их при:
1) отображении прогноза и мастерства в интерфейсе (баллы + оценка),
2) дальнейшей калибровке аналитики (на первом этапе — конвертация результата в экзаменную шкалу).

## Цели (MVP)
1) Ввести **настраиваемую** (через Django admin) шкалу перевода первичных баллов в оценку для `ExamFormat`.
2) Для ОГЭ математики показывать в UI:
   - `Текущий уровень: X/31 (оценка Y)`
   - `Прогноз: P/31 (оценка G)`
3) Учесть условие «геометрия ≥ 2» при вычислении оценки (если условие не выполнено — оценка не может быть выше 2).
4) Определение «геометрии» делаем редактируемым: флаг `TaskType.is_geometry`.

## Не цели (пока)
- Полный пересчёт модели мастерства в “экзаменных первичных баллах” (текущая EMA остаётся 0–100).
- Поддержка всех экзаменов/предметов сразу (делаем только ОГЭ математика, но архитектура расширяемая).
- UI-страница настройки шкал (используем Django admin).

## Источники данных
- `StudentSubjectProfile.exam_format` — “к какому экзамену готовится ученик” по предмету.
- `ExamFormat` — объект формата экзамена (ОГЭ математика 2025/2026 и т.п.).
- `TaskType` — номера заданий; добавляем `is_geometry`.
- `DailySnapshot` — хранит `current_mastery` и `predicted_exam_score` (0–100).

## Новые данные (модели)

### 1) ExamScoreScale (OneToOne к ExamFormat)
**Назначение:** хранить параметры экзаменной шкалы и правила перевода в оценку.

Поля:
- `exam_format` (OneToOne)
- `max_primary_score: int` (для ОГЭ математика = 31)
- `grade_rules: JSON` — список правил для 2..5:
  - `grade` (int 2..5)
  - `min_total` (int)
  - `max_total` (int)
  - `min_geometry` (int|null) — для ОГЭ математика: 2 для 3/4/5, null для 2

Пример для ОГЭ математика 2025 (официальная шкала):
- 2: 0–7
- 3: 8–14, min_geometry=2
- 4: 15–21, min_geometry=2
- 5: 22–31, min_geometry=2

Источник шкалы: PDF “Шкала перевода баллов ОГЭ в оценки в 2025 году”.

### 2) TaskType.is_geometry
**Назначение:** пометить номера заданий, относящиеся к геометрии, чтобы применять условие min_geometry.

Поля:
- `is_geometry: bool = False`

Заполняется в Django admin для нужного `ExamFormat` ОГЭ математики.

## Конвертация 0–100 → “экзаменные баллы и оценка”

### Входные величины
Для `(student, subject)` берем:
- `mastery_100 = latest_snapshot.current_mastery` (0..100)
- `pred_100 = latest_snapshot.predicted_exam_score` (0..100)
- `exam_format = StudentSubjectProfile.exam_format` (fallback на активный формат по предмету)
- `scale = ExamScoreScale` для exam_format (если нет — fallback на поведение “как сейчас”: показываем 0–100)

### Рассчёт первичных баллов (оценка в баллах)
На MVP вводим простую конвертацию:
- `primary = round(mastery_100 / 100 * max_primary_score)`
- `pred_primary = round(pred_100 / 100 * max_primary_score)`
Ограничиваем: `0..max_primary_score`.

### Рассчёт геометрических баллов (для условия min_geometry)
Нужна оценка `geometry_primary`.
На MVP используем приближение:
- `geometry_share = share of geometry points in exam` = `sum(exam_points where TaskType.is_geometry) / sum(exam_points all)`
- `geometry_primary = round(primary * geometry_share)`
- аналогично `pred_geometry_primary`.

Почему так: текущая аналитика 0–100 не хранит раздельно “алгебра vs геометрия”, поэтому либо вводить отдельную аналитику по разделам (не MVP), либо приблизить долей.

В дальнейшем можно заменить на раздельные mastery по двум “модулям”.

### Перевод в оценку 2–5
Функция `grade_from_primary(total_primary, geometry_primary, scale.grade_rules)`:
- находим правило, куда попадает `total_primary` по [min_total, max_total]
- если у правила есть `min_geometry` и `geometry_primary < min_geometry` → понижаем до 2 (или до максимальной оценки, разрешённой правилами без геометрии; для ОГЭ математики это 2)
- возвращаем оценку.

## Изменения в UI
Где показываем (минимум):
- `tutor_dashboard.html` в блоке по предмету:
  - сейчас: `Прогноз: {{ profile.latest_snapshot.predicted_exam_score }}`
  - станет: `Прогноз: {{ pred_primary }}/{{ max_primary }} (оценка {{ pred_grade }})`
  - и рядом: `Текущий: {{ primary }}/{{ max_primary }} (оценка {{ grade }})`
- `student_dashboard.html` и/или `student_learning_settings.html` (аналогично).

## Тестирование
1) Тест модели/сервиса конвертации:
   - mastery=50, max_primary=31 → primary=16
   - проверка порогов 2/3/4/5
2) Тест условия геометрии:
   - total_primary=10 (тянет на 3), но geometry_primary=1 → оценка должна стать 2
3) Тест представления:
   - в `tutor_dashboard` отрендерить строку “Прогноз: …/31 (оценка …)”

## Критерии готовности
- Можно настроить шкалу ОГЭ математики в Django admin.
- Для ученика и репетитора отображается прогноз и текущий уровень в формате “баллы/макс + оценка”.
- Условие “≥2 по геометрии” влияет на оценку (минимум в отображении).
