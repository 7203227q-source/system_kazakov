# Exam Format Goals + SDAMGIA Import Fixes (OGE #25) + Degree/Soft-Hyphen Cleanup — Design

**Goal:**  
1) При выборе/смене формата экзамена (ОГЭ/ЕГЭ и т.п.) варианты должны собираться строго в выбранном формате.  
2) Ученик может менять цель обучения (формат экзамена) после регистрации, и это влияет только на новые варианты.  
3) Импорт задач из SDAMGIA для ОГЭ тип 25 должен стабильно импортировать список задач из `view_many` и давать прозрачный отчёт о причинах “почему не импортировалось”.  
4) Устранить визуальную проблему “гра­ду­сов” (мягкие переносы `\u00ad`) и связанные с формулами SVG/ALT артефакты.

**Non-goals (в рамках этой задачи):**
- Не пересобираем старые варианты при смене цели учеником.
- Не меняем систему начисления XP/аналитики, кроме места выбора exam_format для новых вариантов.

---

## Текущее состояние (что есть сейчас)

1) Вариант (`Assignment`) не хранит `ExamFormat`. При создании варианта репетитор может выбрать exam_format, но есть fallback-логика на “активный формат по предмету”, что может приводить к подбору задач из другого формата.  
2) У профиля ученика (`StudentSubjectProfile`) нет явного поля “формат экзамена как цель”, есть только предмет и числовая цель `target_score`.  
3) Импорт SDAMGIA использует `view_many` и набор фильтров (`skip_no_solution`, `exclude_larin`, `skip_prototype`…), что может приводить к импорту 1 задачи из многих — без достаточного UX объяснения.  
4) В HTML SDAMGIA встречается “гра­ду­сов” из-за `\u00ad` в alt-тексте формул (мягкий перенос). Даже если формула подгрузилась как SVG, этот мусор может “протечь” в UI (ALT, текстовые куски).

---

## Предложение (вариант A — утверждён)

### 1) Данные

**1.1 `Assignment.exam_format`**
- Добавить поле: `Assignment.exam_format = ForeignKey(ExamFormat, null=True, on_delete=SET_NULL, related_name="assignments")`.
- Заполняется при создании варианта и далее не меняется автоматически (история сохраняется).

**1.2 `StudentSubjectProfile.exam_format`**
- Добавить поле: `StudentSubjectProfile.exam_format = ForeignKey(ExamFormat, null=True, on_delete=SET_NULL, related_name="student_profiles")`.
- Это и есть “цель обучения” в разрезе ОГЭ/ЕГЭ.

**Миграции/бэкфилл:**
- Для существующих `StudentSubjectProfile` можно проставить `exam_format` по правилу:
  - Если есть активный формат по предмету (`ExamFormat.is_active=True`) — взять его.
  - Иначе взять первый `ExamFormat` по предмету (детерминированный порядок: `-year`, `id`).
- Для существующих `Assignment`: поле может оставаться `NULL` (приоритет: не ломать историю). При желании — можно проставить, если по задачам варианта можно однозначно вывести формат, но это вне обязательной части.

---

### 2) Логика сборки вариантов “строго в формате”

**Источник формата для новых вариантов (приоритет):**
1) Выбор в UI репетитора при создании варианта (`tutor_create_assignment` / форма `tutor_create_assignment.html`).
2) Иначе `active_profile.exam_format` ученика по выбранному предмету.
3) Иначе активный формат `ExamFormat.is_active=True` по предмету.

**Правило подбора задач:**
- Все задачи для нового варианта должны удовлетворять:
  - `Task.task_type.exam_format == выбранный exam_format`.
- Если задач не хватает — выдаём понятное сообщение (через `messages.error`) и не создаём вариант “смешанный”.

**Хранение:**
- При создании `Assignment` сохраняем `assignment.exam_format = выбранный exam_format`.

---

### 3) Смена цели учеником (ОГЭ→ЕГЭ)

**UI:**
- На странице ученика (дашборд) для активного предмета показать выпадающий список форматов (`ExamFormat`) для этого предмета.
- При выборе формата — POST запрос, который обновляет `StudentSubjectProfile.exam_format`.

**Поведение:**
- Меняется только то, какие задачи/варианты будут предлагаться/генерироваться дальше.
- Уже выданные варианты остаются привязанными к своему `Assignment.exam_format` (не меняем).

---

### 4) SDAMGIA: тип 25 ОГЭ — стабилизация импорта + отчёт

**4.1 Извлечение ID из `view_many`:**
- Парсить только `span.prob_nums a[href*="/problem?id="]` — это реальные задачи списка.
- Не использовать “общий” поиск всех `problem?id=` по странице (на `view_many` их сотни из служебных ссылок).

**4.2 Отчёт для админки импорта:**
- В отчёте показывать агрегированную статистику (уже есть `stats`), но дополнительно:
  - первые N записей `skipped` с причиной (например `no solution`, `prototype`, `larin_source`, `already exists`) и `task_id`.
  - рекомендацию: какие фильтры выключить, если “почти всё отфильтровано”.

**4.3 Управление фильтрами из UI:**
- В форме импорта добавить чекбоксы:
  - “Пропускать без решения”
  - “Пропускать прототипы”
  - “Исключать Ларина”
  - “Пропускать существующие”
- Для ОГЭ тип 25 можно поставить более мягкий дефолт (например, `skip_no_solution=False`), чтобы не получался импорт “1 из 60”.

---

### 5) “Градусы” / “гра­ду­сов” / SVG формулы

Проблема на скрине воспроизводится как артефакт `\u00ad` (мягкий перенос) внутри русских слов в `alt` формул SDAMGIA, например `"48 гра­ду­сов"`.

**5.1 Санитайз `alt`/текста:**
- При обработке HTML контента/решения:
  - удалять `\u00ad`, `\u200b`, `\ufeff` во всём HTML;
  - отдельно пройти по `img` и подчистить `alt`.

**5.2 Корректный `Referer` при скачивании SVG:**
- Сейчас при скачивании изображений referer берётся от `base_url` (например `math-oge.sdamgia.ru`), а формулы лежат на другом домене (`oge.sdamgia.ru`). Это может приводить к блокировкам и показу ALT вместо картинки.
- Правило: `Referer` должен быть `scheme://netloc/` самого `img_url`, если это HTTP(S).

Ожидаемый эффект: формулы перестают “проваливаться” в ALT, а даже если ALT отображается — в нём не будет “гра­ду­сов”.

## Тестирование

**Unit/Integration (Django TestCase):**
1) Создание `Assignment` с выбранным `exam_format` сохраняет его и подбирает задачи только этого формата.
2) Смена `StudentSubjectProfile.exam_format` влияет на новые варианты (можно проверить выбор формата как минимум вьюхой создания).
3) `extract_view_many_ids` возвращает список задач на реальном HTML (подготовленный снапшот/fixture).
4) Санитайзер удаляет `\u00ad` из контента/alt.

---

## Риски и ограничения

- В проекте много логики в `core/views.py`; изменения нужно делать точечно и без больших рефакторингов.
- Если в базе мало задач нужного формата, “строгий” фильтр может чаще приводить к предупреждениям при создании варианта — это нормально и лучше, чем смешанный вариант.
