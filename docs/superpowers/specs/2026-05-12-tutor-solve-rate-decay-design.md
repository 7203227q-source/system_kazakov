# Дашборд репетитора: решаемость по номерам под экзамен ученика + забывание

## Контекст
В панели репетитора есть блок «Решаемость по номерам» (плитки по номеру задания). Сейчас:
- метрика считается по всем `Submission` ученика без привязки к выбранному предмету/экзамену;
- давность решений не влияет на метрику.

Нужно:
1) строить «Решаемость по номерам» для выбранного ученика **по тому экзамену**, к которому он готовится;
2) учитывать естественное забывание: старые решения должны иметь меньший вес.

## Цели
- Метрика «Решаемость по номерам» в `tutor_dashboard` рассчитывается **по предмету**, выбранному справа (тот же `subject_id`, что у графика мастерства/прогноза).
- Набор номеров/типов задач берётся из `ExamFormat`, выбранного для этого предмета в `StudentSubjectProfile.exam_format` (fallback на активный формат по предмету).
- Решаемость учитывает давность решения через экспоненциальное затухание веса.
- Для предотвращения «накрутки попытками» используется последняя попытка ученика по каждой задаче.

## Не цели
- Пересчёт/миграция исторических данных.
- Изменение логики начисления XP или SRS.
- Новый UI-конструктор для выбора формата отдельно от предмета (используем текущую модель выбора предмета справа).

## Определения
- **Предмет аналитики**: `chart_subject_id` в `tutor_dashboard`.
- **Экзамен ученика**: `StudentSubjectProfile.exam_format` для `(student, subject)`, иначе активный формат `ExamFormat(is_active=True)` по предмету.
- **Номер**: `TaskType.number` внутри выбранного `ExamFormat`.
- **Последняя попытка по задаче**: последнее `Submission` ученика по конкретной `Task` (по `created_at`).

## Источники данных
- `StudentSubjectProfile(student, subject, exam_format)`
- `ExamFormat(subject, ...)`
- `TaskType(exam_format, number, ...)`
- `Task(task_type, topic(subject), ...)`
- `Submission(student, task, is_correct, created_at, ...)`

## Алгоритм расчёта (взвешенная решаемость)
Для каждого номера `n` (каждый `TaskType` в выбранном `ExamFormat`):
1) Получаем множество задач `Task` для данного `TaskType` (в пределах выбранного `ExamFormat`).
2) Для каждой `Task` берём **последний** `Submission` ученика (если есть).
3) Для каждой задачи с последней попыткой считаем:
   - `age_days = (today - submission.created_at.date()).days`
   - `weight = 0.5 ** (age_days / half_life_days)`
   - `value = 1`, если `submission.is_correct=True`, иначе `0`
4) Итог по номеру:
   - `weighted_total = sum(weight)`
   - `weighted_correct = sum(weight * value)`
   - `rate = weighted_correct / weighted_total * 100` (если `weighted_total > 0`, иначе `None`)
5) Для вывода в UI:
   - `rate` (взвешенный процент)
   - `total_unique = количество задач с хотя бы одной попыткой (последняя попытка существует)`
   - `correct_unique = количество задач, где последняя попытка верная`

Параметр:
- `half_life_days = 14` (константа в серверном коде; при необходимости позже вынесем в настройку).

## Правила выбора экзамена (формата)
1) Если у ученика есть `StudentSubjectProfile` для выбранного предмета:
   - если `exam_format_id` задан: используем его;
   - иначе: используем активный формат по предмету (`is_active=True`, самый свежий по `year desc`).
2) Если профиля нет: fallback на активный формат по предмету.

## Производительность и запросы
Цель: не делать N+1 по задачам.

Рекомендуемая стратегия:
- Определить `selected_exam_format`.
- Получить `task_types = TaskType.objects.filter(exam_format=selected_exam_format).only('id','number','name')`.
- Получить последние решения ученика по задачам выбранного формата одним запросом:
  - фильтр `Submission.student=selected_student` и `Submission.task__task_type__exam_format=selected_exam_format`
  - сгруппировать по `task_id` и взять максимум `created_at` (Subquery/OuterRef или `distinct('task_id')` если Postgres; код должен быть совместим с текущей БД проекта)
- Дальше в Python:
  - посчитать веса, `rate`, `correct_unique/total_unique` по `task_type.number`.

Ожидаемое поведение при отсутствии данных:
- если у номера нет попыток: `rate=None`, `correct=0`, `total=0` и в UI показываем `—`.

## UI
- В `tutor_dashboard.html` в блоке плиток «Решаемость по номерам»:
  - `{{ item.rate }}` становится взвешенной решаемостью;
  - `{{ item.correct }}/{{ item.total }}` остаётся как `correct_unique/total_unique`.
- Цвет плитки (градиент) продолжает использовать `data-rate`.

## Тестирование
- Юнит-тест на `tutor_dashboard`:
  - создаём ученика, формат, TaskType, несколько задач;
  - создаём `Submission` с разной датой (`today` и `today - 14 days`) и разной корректностью;
  - проверяем, что `task_type_rates` меняется при изменении давности и использует выбранный `exam_format` ученика.

## Критерии готовности
- В панели репетитора плитки «Решаемость по номерам» меняются при переключении предмета справа.
- Плитки строятся по номерному ряду формата ученика, а не по фиксированному набору.
- Старые решения оказывают меньший вклад (проверяется тестом на half-life).
