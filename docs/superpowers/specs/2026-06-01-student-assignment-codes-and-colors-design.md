# Student Assignment Codes & Colors (Student Dashboard) — Design

**Цель:** чтобы ученик мог быстро и однозначно сопоставлять варианты на компьютере и телефоне при загрузке фото решения, даже если вариантов несколько.

## Контекст (как сейчас)

- На дашборде ученика карточки вариантов рендерятся в [student_dashboard.html](file:///workspace/core/templates/core/student_dashboard.html#L264-L356).
- На странице решения варианта загрузка фото привязана к конкретному `Submission` и делается через `/upload/<upload_token>/` (QR) или `/api/submission/<submission_id>/upload/` (внутри страницы решения) — это не зависит от “номера варианта”.
- В модели `Assignment` уже есть поле `student_seq` (порядковый номер по ученику): [models.py](file:///workspace/core/models.py#L358-L395). Сейчас оно заполняется только в части сценариев генератора.

## Требования

1) У каждого варианта ученика должен быть стабильный **трёхзначный код** `#001`, `#002`, … (порядок по ученику).
2) Этот код должен отображаться:
   - в списке “Мои задания (Варианты)” на дашборде ученика;
   - на странице решения варианта;
   - на мобильной странице загрузки фото по QR.
3) Варианты на дашборде ученика должны иметь “легко различимые” визуальные отличия:
   - детерминированная цветная метка/фон по коду (одинаково на ПК и телефоне).

## Решение

### 1) Источник кода

Использовать `Assignment.student_seq` как “номер варианта по ученику”.

- Формат отображения: `#{student_seq:03d}` (например `#007`).

### 2) Гарантия заполнения `student_seq`

**На создание новых вариантов**
- Во всех местах создания `Assignment` гарантировать заполнение `student_seq` (даже если заголовок вводится вручную).
- Правило: `student_seq = max(student.student_seq) + 1` в транзакции (чтобы избежать гонок).

**Для существующих вариантов**
- При первом заходе ученика на дашборд (или при открытии страницы решения) “дозаполнять” отсутствующие `student_seq` для этого ученика:
  - выбрать все `Assignment` ученика с `student_seq IS NULL` (не удалённые);
  - отсортировать по `created_at`, затем по `id`;
  - присвоить последовательные номера, начиная с `max(existing student_seq) + 1`;
  - сохранить пачкой в одной транзакции.

### 3) Цветовая метка (детерминированная)

Цвет вычисляется от `student_seq`:
- `palette_index = (student_seq % N)` (например N=6–8 цветов).
- В UI показывать небольшой цветной элемент (badge/полоса/кружок) рядом с `#001`, чтобы не ухудшать читаемость карточки.

Важно: цвет должен быть одинаковый для `#001` на дашборде и на странице решения (и по возможности на mobile upload).

## Изменения UI

### Student dashboard (список вариантов)
- В каждой карточке варианта:
  - добавить `#XYZ` перед названием;
  - добавить цветную метку.

### Student solve assignment (страница решения)
- В заголовке страницы рядом с `assignment.title` показывать `#XYZ` и цветную метку.

### Mobile upload (страница загрузки фото)
- В заголовке добавить строку вида: `Вариант #XYZ` (и цветную метку).
- Приоритет: обеспечить однозначность сопоставления “какой вариант” перед тем, как ученик делает фото.

## Тестирование (минимум)

- Тест на гарантированную генерацию `student_seq` для вариантов без номера.
- Тест, что дашборд/страница решения содержит `#001` для первого варианта.
- (Опционально) тест детерминированности цвета: одинаковый `student_seq` → одинаковый CSS-класс/значение.
