## Контекст

Нужно связать каждую задачу ученика с интерактивной векторной доской, чтобы ученик и репетитор могли одновременно работать (двусторонний ввод), а результаты сохранялись и были доступны ученику для повторения.

Ограничения текущей платформы:
- Деплой сейчас WSGI/Gunicorn без Channels/Redis.
- Поэтому MVP делаем на HTTP (push событий + pull), но проектируем протокол так, чтобы позже перейти на WebSocket.

Важно:
- `preferred_theme` (classic/dota/cs2/ussr) — это сеттинг контента задач.
- UI-тема (light/dark/…) — отдельно и не влияет на условие задачи.

## Требования

1) В БД должна быть чёткая связь: ученик ↔ вариант ↔ задача ↔ доска.
2) Несколько досок на одну задачу (история).
3) Векторный ввод (мышь/перо/планшет), инструменты: pen, eraser, простые фигуры (линия/прямоугольник/треугольник), быстрая таблица, цвет, толщина.
4) Условие задачи должно автоматически “подгружаться” на доску и **добавляться на холст как объект** (не просто панель сверху).
5) Сохранение по кнопке + автосейв.
6) Роли:
   - ученик видит условие и свою доску,
   - репетитор видит условие (в сеттинге ученика) и может раскрыть решение задачи,
   - доступ строго только связанной паре tutor↔student по assignment.

## Модель данных

### WhiteboardSession

Одна “доска/версия” для конкретной задачи ученика в конкретном варианте.

Поля:
- `student` (User, role=student)
- `tutor` (User, role=tutor) — владелец варианта
- `assignment` (Assignment)
- `task` (Task)
- `title` (string, опционально, например “Доска 1”)
- `snapshot_json` (Text/JSON) — текущее состояние холста (векторные объекты)
- `created_at`, `updated_at`

Индексы:
- `(student, assignment, task, created_at)`

### WhiteboardEvent

Инкрементальные события для синхронизации между двумя клиентами.

Поля:
- `session` (FK WhiteboardSession)
- `seq` (auto-increment per session) или `id` как курсор
- `kind` (string): `stroke_start`, `stroke_points`, `stroke_end`, `shape_add`, `erase`, `set_object`, `delete_object`
- `payload_json` (Text/JSON)
- `author` (User)
- `created_at`

## Протокол холста (векторная модель)

Состояние холста — набор объектов:

```json
{
  "version": 1,
  "objects": [
    { "id": "obj_1", "type": "pen", "points": [[x,y],...], "color": "#111827", "width": 3 },
    { "id": "obj_2", "type": "triangle", "a":[x,y], "b":[x,y], "c":[x,y], "stroke":"#2563eb", "width": 3 },
    { "id": "obj_3", "type": "table", "x": 120, "y": 80, "rows": 4, "cols": 4, "cellW": 80, "cellH": 48, "stroke":"#9ca3af", "width": 2 },
    { "id": "obj_task", "type": "task_card", "x": 32, "y": 32, "w": 520, "h": 260, "content_html": "<p>...</p>", "images": ["..."] }
  ]
}
```

### Условие как объект (task_card)

При первом открытии доски автоматически добавляется объект `task_card`:
- позиция по умолчанию (например, левый верхний угол),
- содержит HTML условия (в сеттинге ученика) и список ссылок на изображения (если есть).

Репетитор и ученик видят одинаковый `task_card` (общее состояние), но:
- репетитор может открыть “Решение” отдельно в UI (не обязательно объектом на холсте).

## Эндпоинты (MVP на HTTP)

### Страница доски

- `GET /board/<session_id>/` — HTML (условие+доска+панель инструментов+список досок).
- `POST /board/<assignment_id>/<task_id>/create/` — создать новую доску (version) для пары student+assignment+task.
- `GET /board/list/?assignment_id=...&task_id=...&student_id=...` — список досок для выбора.

### Синхронизация

- `POST /board/<session_id>/events/append/` — принять пачку событий от клиента.
- `GET /board/<session_id>/events/pull/?after=<event_id>` — вернуть новые события после курсора.
- `POST /board/<session_id>/save/` — сохранить snapshot (кнопка “Сохранить”).

## UI (минимальный, не перегруженный)

Лейаут:
- верхняя полоса: название варианта/задачи, выбор доски (dropdown), кнопки “Сохранить”, “Новая доска”.
- тулбар: pen, eraser, line, rect, triangle, table; цвет (5–6 кнопок), толщина (3–4 пресета).
- холст: SVG (вектор) + Pointer Events.

Автосохранение:
- таймер 45–60 сек и `beforeunload` (если есть несохранённые изменения).

## Доступ и безопасность

- Ученик: доступ только к своим `WhiteboardSession` по assignment, где он `assignment.student`.
- Репетитор: доступ только если `assignment.tutor == request.user` и ученик соответствует.
- Нельзя смотреть доски других учеников/репетиторов.

## План миграции на WebSocket (позже)

- Транспорт событий меняется на WS, модель `WhiteboardEvent` и формат payload остаются.
- Серверная часть: Channels + Redis, ASGI-сервер вместо чистого WSGI.
