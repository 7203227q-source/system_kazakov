# Tutor Dashboard — предметный переключатель и предметная статистика (Design Spec)

**Цель:** В дашборде тьютора статистика по выбранному ученику должна корректно **разделяться по предметам** (минимум: математика/физика) и переключаться одним общим переключателем предмета **вверху страницы**.

## Контекст (как сейчас)

- View: `core/views.py::tutor_dashboard`
- Template: `core/templates/core/tutor_dashboard.html`
- Уже есть `subject_id` в querystring, который влияет на:
  - график прогресса (`DailySnapshot` по `subject`)
  - “решаемость по номерам” (сейчас через `active_exam_format`, а не напрямую по subject)
- **Не предметные сейчас:** метрики “Попыток” и “Точность” считаются по всем `Submission` ученика без фильтра по предмету.

## Требования

### R1. Общий переключатель предмета сверху

- В верхней части страницы (header) добавить переключатель предмета для **выбранного ученика**.
- Переключатель должен быть видим, когда выбран ученик (`selected_student`).
- Источник списка предметов — предметные профили ученика (`selected_student.subject_profiles`).
- UI: кнопки/табы (pills) по предметам (например “Математика”, “Физика”, …).
- По клику переключателя должна открываться та же страница с параметрами:
  - `student_id=<id>`
  - `subject_id=<subject_id>`
  - сохранить `range=<текущее значение>` (30/90/365)

### R2. Вся “Прогноз и Аналитика” — строго по выбранному предмету

При выбранном `subject_id`:

1) **Попыток** (`student_total_submissions`) и **Точность** (`student_correct_rate`) считаются **только по этому предмету**.
   - Фильтр по subject (даже если у профиля не выбран exam_format):
     - `Submission.objects.filter(student=selected_student, task__topic__subject_id=subject_id)`

2) **График прогресса** остаётся по `DailySnapshot(subject=selected_subject)` (как сейчас), но должен использовать тот же `subject_id`, что и верхний переключатель.

3) **Решаемость по номерам** (`task_type_rates`) должна переключаться вместе с предметом.
   - Для списка номеров используем “активный exam_format” для выбранного предмета:
     - если в `StudentSubjectProfile.exam_format` установлен — берём его
     - иначе — fallback на `ExamFormat.objects.filter(subject_id=subject_id, is_active=True)...first()`
   - При расчёте базы сабмишнов:
     - сначала фильтр по subject
     - дополнительно можно сужать до `active_exam_format` (чтобы номера и данные совпадали), но **предметный фильтр обязателен**.

### R3. Убрать/не использовать локальный select предмета внутри аналитики

- Текущий `<select name="subject_id">` в блоке аналитики не должен дублировать управление.
- Поведение:
  - либо удалить select,
  - либо сделать read-only/скрытым и синхронизировать с верхним переключателем.
- В этой задаче: **удаляем** (предпочтительно), чтобы был один источник истины — верхний переключатель.

### R4. (Опционально, но рекомендуется) Фильтрация списка вариантов по предмету

Чтобы “всё по предмету” воспринималось последовательно:
- списки “активные/завершённые варианты” справа фильтровать по `Assignment.exam_format.subject_id == subject_id` (если у `Assignment` есть exam_format; в проекте поле есть).
- Если `subject_id` не задан — показывать как раньше.

## Нефункциональные требования

- Никаких изменений для студентов/админки; только tutor dashboard.
- Все изменения покрыть тестами на уровне Django TestCase.
- Не ломать существующие querystring-параметры: `student_id`, `range`.

## Acceptance Criteria (что считаем “готово”)

1) При переключении предмета сверху:
   - меняются “Попыток/Точность”,
   - меняется график,
   - меняются “решаемость по номерам” и подпись активного формата.
2) Метрики “Попыток/Точность” не учитывают решения другого предмета.
3) Если `StudentSubjectProfile.exam_format` не задан, метрики всё равно считаются по subject (и решаемость отображается по fallback-формату).

## Тесты (минимум)

- Новый тест: `tutor_dashboard` при `subject_id=math` показывает totals/accuracy только по math, при `subject_id=phys` — только по phys.
- Тест на сохранение `range` при переключении предмета (querystring сохраняется).
- (Если делаем R4) тест: список assignments фильтруется по subject.
