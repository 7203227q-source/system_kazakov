## Контекст

Импорт из ссылки `.../test?a=view_many...` получает список ID задач из HTML страницы.

Проблема: на странице `view_many` присутствуют дополнительные ссылки на другие задачи (например, «похожие/аналоги/лайки»), которые тоже содержат `problem?id=...`. Текущий парсер берёт все такие `problem?id` и раздувает список (например, ожидали ~100 задач, получаем тысячи).

Пример:  
`https://math-ege.sdamgia.ru/test?a=view_many&cat_id[]=...&filter=all`

## Цель

- Импортировать только те задачи, которые реально перечислены в `view_many` по заданным фильтрам.
- Не собирать ID из блоков «похожие/аналоги/лайки» и прочих дополнительных ссылок на странице.

## Предлагаемое решение

### Строгий парсинг ID из заголовка задачи

В `fetch_view_many_ids()` извлекать ID только из заголовочного блока задачи, который на sdamgia имеет вид:

- контейнер/фрагмент с `class="prob_nums"`
- шаблон текста: `Тип … № <a href="/problem?id=NNNNN">NNNNN</a>`

То есть извлекаем `NNNNN` только из «шапки» каждой задачи.

### Fallback

Если по строгому шаблону не найдено ни одного ID (на случай изменения верстки), используем текущую старую эвристику (общий поиск `problem?id=`) как запасной вариант.

## Критерии готовности

- Для `view_many` ссылка больше не раздувает список из-за «похожих» задач.
- Количество извлечённых ID близко к ожидаемому количеству задач в выдаче.
- Поведение для одиночных `problem?id=...` и списка ID не меняется.
