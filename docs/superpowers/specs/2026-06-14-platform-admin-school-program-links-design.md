## Контекст

Сущности школьного контура для `Математика, 7 класс` уже существуют в системе:

- `LearningTrack`
- `CurriculumUnit`
- `CurriculumTopic`
- `LearningTaskType`
- `SchoolTaskMeta`
- `StudentLearningPlan`
- `PlanItem`

Но они зарегистрированы только в стандартном Django admin.

Пользовательская проблема:

- администратор работает в кастомной панели `/platform-admin/`;
- в этой панели нет видимого раздела для школьной программы;
- поэтому невозможно понять, куда нажимать для создания и редактирования программы 7 класса.

## Цель

Добавить в `platform-admin` отдельный раздел `Школьная программа`, чтобы:

- все нужные ссылки были собраны в одном месте;
- администратору не нужно было вручную искать URL;
- вход в работу со школьным контуром происходил из привычной кастомной панели.

## Границы

В этот объём входит:

- новый пункт меню в `platform-admin`;
- новая страница `/platform-admin/school-program/`;
- карточки со ссылками на существующие admin-страницы моделей;
- блок `Быстрый старт` с пошаговой инструкцией.

В этот объём не входит:

- полный перенос CRUD-форм из Django admin в `platform-admin`;
- новые модели;
- изменение логики школьного контура;
- отдельные серверные API для создания/редактирования этих сущностей.

## Ключевое решение

Реализуется **гибридный вариант**:

- администратор входит через `platform-admin`;
- видит отдельный раздел `Школьная программа`;
- из него открывает нужные сущности по удобным кнопкам;
- сами формы редактирования на этом этапе остаются в существующем Django admin.

Это решает UX-проблему без лишней большой разработки.

## Маршрут

Новый маршрут:

- `/platform-admin/school-program/`

Новая view:

- `admin_school_program`

Новый пункт меню:

- `Школьная программа`

## Состав страницы

На странице должны быть карточки для следующих сущностей:

1. `Курсы`
- ведёт на список `LearningTrack`
- есть кнопка `Открыть список`
- есть кнопка `Добавить`

2. `Разделы`

- есть кнопка `Открыть список`
- есть кнопка `Добавить`

3. `Темы`
- ведёт на `CurriculumTopic`
- есть кнопка `Открыть список`
- есть кнопка `Добавить`

4. `Типы заданий`
- ведёт на `LearningTaskType`
- есть кнопка `Открыть список`
- есть кнопка `Добавить`

5. `Связка заданий`
- ведёт на `SchoolTaskMeta`
- есть кнопка `Открыть список`

## Быстрый старт

На странице должен быть отдельный блок `Быстрый старт`.

В нём отображаются шаги:

1. Открыть курс `Математика, 7 класс`
2. Создать или проверить разделы
3. Добавить темы программы
4. Добавить типы заданий
5. Привязать задания через `SchoolTaskMeta`
6. Создать индивидуальный план

Цель блока:

- не просто дать ссылки;
- а подсказать рабочую последовательность действий.

## UX-требования

- Визуально страница должна соответствовать стилю текущего `platform-admin`.
- Новый пункт меню должен быть в том же боковом сайдбаре, что и остальные разделы.
- Текущий раздел должен визуально подсвечиваться как активный.
- Карточки должны быть читаемыми и не перегруженными.
- Названия — на русском языке.
- Внутри карточек можно использовать английские системные имена только как вспомогательные подписи, если нужно.

## Доступ

Доступ к новому разделу должен быть только у пользователей с ролью `admin`.

Поведение должно быть согласовано с остальными страницами `platform-admin`.

## Критерии готовности

- В боковом меню `platform-admin` появился пункт `Школьная программа`.
- Страница `/platform-admin/school-program/` открывается только для администратора.
- На странице отображаются все 7 карточек сущностей школьного контура.
- У каждой карточки есть удобные ссылки `Открыть список` и `Добавить`.
- На странице есть блок `Быстрый старт`.
- Администратор может начать работу с программой 7 класса, не выходя из привычной `platform-admin` навигации.

## Итоговая рекомендация

Это правильный промежуточный шаг:

- не заставляет пользоваться чистым Django admin как единственной точкой входа;
- быстро решает навигационную проблему;
- создаёт удобную точку входа в школьный контур;
- оставляет возможность позже заменить ссылки полноценными внутренними CRUD-экранами в `platform-admin`.
