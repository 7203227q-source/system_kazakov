## Контекст

Текущий импорт с РешуЕГЭ (`/platform-admin/reshuege-import/`) обрабатывает ссылки `/test?a=view_many...`, но:

- распаковывает максимум 500 ID из списка;
- импортирует максимум 25 задач за запуск (по лимиту UI/серверных ограничений);
- содержит автоостановку при 0 OK после N проверок.

Нужно уметь импортировать все задачи из списка и понимать их реальное количество.

## Цель

- Импортировать все задачи из `view_many` (в пределах заданного верхнего лимита за запуск).
- Убрать автоостановку.
- Показывать, сколько всего задач найдено в списке (чтобы было понятно, «сколько ещё осталось»).

## Поведение

### Источник ID

- При вводе ссылки `/test?a=view_many...` парсер извлекает все `problem?id=...` со страницы списка.
- Лимит распаковки ID увеличивается так, чтобы покрывать реальный объём списка, но не приводить к бесконтрольному росту нагрузки.

### Лимит импорта

- Поле «Лимит» трактуется как «сколько задач сохранить в БД за запуск».
- Разрешённый максимум за запуск: `10_000`.
- Если найдено меньше — импортируется всё найденное.
- Если найдено больше — импортируются первые `10_000` (в порядке списка), а UI явно показывает «всего найдено».

### Прогресс

- UI показывает:
  - «Скачано X из Y» (где `Y = min(лимит, всего_найдено)`)
  - «Проверено A / всего_найдено»
  - счётчики OK/SKIP/ERR и последнюю обработанную строку.

### Остановка

- Убирается автоостановка при 0 OK после N проверок.
- Остаётся ручная кнопка «Остановить».

## Технические изменения

- `fetch_view_many_ids`: поднять лимит распаковки (или сделать зависимым от лимита импорта, но не ниже 10k).
- `admin_reshuege_import_start`: перестать ограничивать `limit` до 25; ограничивать до 10k.
- JS-импорт: продолжать до `Y`, без автоостановки.
