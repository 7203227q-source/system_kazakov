# Московское время + “сегодня/вчера” в чате и комментариях (Design Spec)

**Цель:** Сделать отображение времени в интерфейсе в **московском часовом поясе** и выводить человеко‑читаемые метки времени для **чата** и **комментариев к заданиям**: `сегодня 14:05`, `вчера 21:10`, иначе `12.05 09:00` (год — только если не текущий).

## Область работ (scope)

Только:
- Чат (список диалогов + сообщения)
- Комментарии к решениям/заданиям (SubmissionComment)

Не трогаем пока:
- Историю решений
- Дашборды
- Прочие страницы

## Текущее состояние

- `examprep/settings.py`:
  - `TIME_ZONE = "UTC"`
  - `USE_TZ = True`
- Комментарии в `student_solve_assignment.html` форматируются через `{{ c.created_at|date:"d.m H:i" }}`
- В чате (`chat.html`) время в сообщениях отображается строкой из API (`msg.created_at`), а в списке диалогов используется `{{ d.last_message.created_at|date:"H:i" }}`

## Требования

### R1. Московский часовой пояс в Django
- В settings установить `TIME_ZONE = "Europe/Moscow"`.
- `USE_TZ` оставить включённым (`True`), чтобы:
  - в БД хранить UTC,
  - в отображении/локализации использовать МСК.

### R2. Единый форматтер времени для UI

Нужна одна функция/фильтр для форматирования datetimes:
- если дата == сегодня (в МСК): `сегодня HH:MM`
- если дата == вчера (в МСК): `вчера HH:MM`
- иначе: `DD.MM HH:MM`
- если год не текущий: `DD.MM.YYYY HH:MM`

### R3. Комментарии: использовать новый форматтер
- В шаблонах где показывается `SubmissionComment.created_at`, заменить на `|ui_datetime` (например).

### R4. Чат: время сообщений и диалогов в новом формате

Чат должен показывать время в том же стиле:
- в списке диалогов (последнее сообщение)
- в “пузырях” сообщений

Архитектурно:
- фронт не должен вычислять “сегодня/вчера” самостоятельно
- API возвращает готовую строку, например `created_at_label`

## Реализация (high level)

1) Добавить `core/templatetags/ui_datetime.py` с template filter `ui_datetime`.
2) Добавить python helper (например `core/utils/datetime_ui.py`) с функцией `format_ui_datetime(dt, tz="Europe/Moscow")`, которую используют и:
   - template filter
   - chat API serializer
3) В `chat` API (views_chat или где реализовано) изменить payload:
   - `created_at` оставить как ISO (если нужно), но для UI добавить `created_at_label`
4) В `chat.html`:
   - list view: заменить `|date:"H:i"` на `|ui_datetime`
   - message bubble: использовать `msg.created_at_label`
5) В `student_solve_assignment.html`:
   - заменить форматирование даты комментария на `|ui_datetime`

## Тестирование

- Unit test для formatter’а:
  - dt сегодня/вчера/другая дата → ожидаемые строки
- Template test для comments (страница задания) — что отдаёт `сегодня/вчера` (используя freeze time или ручное сравнение)
- Chat API test — что возвращается поле `created_at_label` и оно не пустое

## Acceptance Criteria

- После деплоя в чате и в комментариях время отображается в МСК и в нужном формате:
  - сегодня/вчера
  - дата+время для более старых
- Нет расхождений формата между чатом и комментариями.
