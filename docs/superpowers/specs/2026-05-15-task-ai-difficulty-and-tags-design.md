# Спека: ИИ-оценка сложности задач и теги методов/свойств по всей базе

Дата: 2026-05-15  
Статус: draft (готово к ревью)

## Контекст и цель

Нужно с помощью ИИ:
1) Оценить **сложность каждой задачи**:
   - относительно **всего экзамена** (в рамках конкретного `ExamFormat`)
   - относительно **типа задания** (`TaskType`, номер в КИМе)
2) Проставить **теги** к каждой задаче: какие математические методы/свойства/темы применяются.
3) Сделать это **по всей базе задач** и добавить **отображение/фильтры** в `tutor_task_bank`.

Важно: на первом этапе используем **только контентную оценку ИИ** (без калибровки по статистике решаемости).

## Ключевая идея (почему так)

ИИ не может надёжно “знать” распределение сложности по всей нашей базе, поэтому:
- ИИ выдаёт **абсолютную** оценку сложности `1–100` (на основе условия/решения).
- Относительные метрики считаются **после прогона по базе**:
  - `exam_percentile` — позиция задачи среди задач одного `ExamFormat`
  - `type_percentile` — позиция среди задач одного `TaskType` (в рамках `ExamFormat`)

Это даёт “настоящую относительность” и стабильность при обновлениях базы (можно пересчитать процентили).

## Данные и модели

### Новые поля сложности (Task)
Не используем существующее поле `Task.difficulty` как “AI difficulty”, потому что оно уже влияет на начисление XP в текущей логике.

Добавляем:
- `Task.ai_difficulty_raw` (int 1–100, nullable) — абсолютная оценка сложности от ИИ.
- `Task.ai_difficulty_exam_percentile` (int 0–100, nullable) — процентили относительно экзамена.
- `Task.ai_difficulty_type_percentile` (int 0–100, nullable) — процентили относительно типа задачи.
- `Task.ai_annotated_at` (datetime, nullable) — когда задача была размечена.
- `Task.ai_annotation_version` (str/int, nullable) — версия схемы/промпта (для пере-прогона).

### Теги (нормализованный справочник)
Чтобы обеспечить фильтрацию в UI на любой БД, делаем нормализованные таблицы:

- `TaskTag`:
  - `name` (уникально в рамках `kind`, хранить в нормализованном виде, например lower/trim)
  - `kind` (enum): `method`, `property`, `topic`, `other`

- связь `Task <-> TaskTag` через `ManyToMany` (можно через explicit through, если понадобится хранить `source=ai/manual`).

**Почему не JSON в Task:** JSON удобен для хранения, но сложнее для поиска/фильтров и может быть ограничен конкретной СУБД. M2M даёт простой `filter(tags=...)` в Django.

### Связь с существующим subtype_tag
Существующее `Task.subtype_tag` остаётся как есть.
Дополнительно можно:
- либо заполнять `subtype_tag` автоматически **только если он пустой** (опциональный флаг команды),
- либо держать AI-теги отдельно и не трогать `subtype_tag`.

На первом этапе: **не перезаписывать** `subtype_tag` автоматически (чтобы не ломать текущие фильтры/ручные правки). Можно добавить опцию в команду для заполнения пустых.

## Промпт и формат ответа ИИ

Источник: `TaskVariant.content` + `TaskVariant.solution` (classic), плюс контекст:
- `ExamFormat` (название/год)
- `TaskType` (номер/название/макс. балл/признак развёрнутого ответа)

ИИ должен вернуть **только JSON**:
- `difficulty_raw`: integer 1..100
- `methods`: array[string]
- `properties`: array[string]
- `topics`: array[string]
- `short_subtype`: string (короткая классификация, 1–4 слова; опционально)

Нормализация на нашей стороне:
- trim
- collapse spaces
- lowercasing для ключей `TaskTag.name` (отображать можно с исходным регистром, но хранить нормализованно)

## Пакетный прогон по всей базе

Делаем management command, который:
- выбирает задачи батчами (например по 100–500)
- пропускает уже размеченные задачи (если нет `--force`)
- пишет прогресс в лог
- имеет rate-limit/backoff
- на каждом батче коммитит изменения в БД
- после завершения:
  - пересчитывает `exam_percentile` и `type_percentile` по всей базе (или по затронутому `exam_format`)

Повторный прогон:
- по флагу `--force` или если `ai_annotation_version` отличается.

## Изменения в UI: tutor_task_bank

### Отображение в списке задач
В карточке/строке задачи добавить:
- `AI сложность: <raw>/100`
- `Экзамен: <exam_percentile>%` (или “перцентиль”)
- `Внутри типа: <type_percentile>%`
- теги: бейджи (method/property/topic), ограничить показ (например первые 6) + “ещё N”.

### Фильтры
Добавить:
- фильтр по `AI сложность (raw)` диапазон (min/max)
- фильтр по `exam_percentile` диапазон (min/max)
- фильтр по тегу:
  - одиночный select из наиболее частых тегов в текущем скоупе (subject/exam_format/type)
  - + текстовый поиск по тегу (contains) как fallback

## Критерии приёмки

1) Можно запустить прогон по всей базе: у задач появляются `ai_difficulty_raw` и теги.
2) Процентили корректно считаются в рамках:
   - одного `ExamFormat`
   - одного `TaskType`
3) В `tutor_task_bank` видны AI-метрики и теги; фильтры работают.

## Риски и ограничения
- Стоимость и скорость прогона зависят от числа задач и выбранной модели.
- Разметка будет шумной: потребуется итеративная нормализация/синонимы (это нормально).
- Для задач без `task_type`/`exam_format` часть метрик (процентили) не будет считаться — нужно решить, хотим ли мы принудительно заполнить `task_type` перед прогоном.
