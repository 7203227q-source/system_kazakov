# Дизайн: проверка решений у репетитора, правка баллов, deep-link комментариев, live-обновление вариантов

Дата: 2026-05-14  
Статус: согласовано пользователем, готово к планированию

## Контекст и проблемы

1) Репетитор не видит в одном месте:
   - загруженное учеником фото решения (черновик/решение);
   - вердикт ИИ по этому фото;
   - возможность быстро поставить «итог репетитора».

2) Репетитор хочет:
   - перегенерировать проверку ИИ (с кулдауном 2 минуты);
   - изменить балл, выданный ИИ, **но так, чтобы ученик продолжал видеть только ИИ**, а правка репетитора шла в аналитику/прогноз.

3) Навигация по комментариям ученика неудобна:
   - из карточки ученика переход ведёт в журнал, но не видно, к какой задаче относится комментарий.

4) После публикации вариантов репетитором ученик должен видеть их на дашборде «почти сразу», без ручного обновления страницы.

## Ключевые решения (зафиксированы)

1) **Ученик видит только оценку ИИ** (как сейчас): `primary_score/is_correct/ai_feedback`.
2) Репетитор может поставить **«итог репетитора»**, который:
   - **не изменяет** сохранённые поля ИИ;
   - **полностью заменяет** оценку ИИ в аналитике/прогнозе (если задан).
3) Итог репетитора редактируется **только для 2-й части** (там, где есть ИИ-проверка по фото).
4) Перегенерация ИИ доступна репетитору с **кулдауном 120 секунд** (как у ученика).
5) Комментарии: делаем deep-link на конкретную задачу/попытку (submission) и автораскрытие.
6) Live-обновление вариантов у ученика: лёгкий polling (10–15 сек) для списка «Мои задания».

## UX / пользовательские сценарии

### A) Репетитор: просмотр решения ученика и вердикта ИИ

Экран: `tutor_assignment_view` (вариант репетитора).

В карточке задачи (если есть `Submission`):
1) Блок «Решение ученика»:
   - миниатюра фото (кликабельно, lightbox).
2) Блок «Вердикт ИИ»:
   - «Оценено: N баллов» + текст `ai_feedback_display_html`.
3) Блок «Итог репетитора»:
   - числовое поле `0..max_points` (или селект);
   - кнопка «Сохранить»;
   - отображение «Итог репетитора сохранён» + время.
4) Кнопка «Перепроверить ИИ»:
   - вызывает API;
   - дизейблится и показывает таймер до следующей попытки (120 сек).

### B) Репетитор: переход по комментарию ученика к нужной задаче

Источник: бейдж «Вопросы: N» на карточке ученика (tutor_dashboard).

Поведение:
- ссылка ведёт на `tutor_student_history/<student_id>?submission_id=<id>`
- страница журнала:
  - находит submission по `submission_id`;
  - раскрывает нужный день/вариант/карточку задачи;
  - скроллит к ней и подсвечивает (например, жёлтой рамкой 2–3 сек);
  - помечает комментарии как «seen_by_tutor_at».

### C) Ученик: варианты появляются без refresh

Экран: `student_dashboard`.

Поведение:
- блок «Мои задания (Варианты)» обновляется polling-ом раз в 10–15 секунд:
  - только если вкладка активна (Page Visibility API);
  - без перезагрузки страницы.

## Модель данных

### Новые поля в `Submission`

Добавить:
- `tutor_primary_score: IntegerField(null=True, blank=True)` — итог репетитора для 2-й части
- `tutor_scored_at: DateTimeField(null=True, blank=True)`
- опционально: `tutor_scored_by: ForeignKey(User, null=True, blank=True)` (если нужен аудит)

Правило приоритета для аналитики:
```
effective_primary_score = tutor_primary_score if tutor_primary_score is not None else primary_score
```

## API / права доступа

### 1) Выставить итог репетитора
`POST /api/tutor/submission/<id>/override_score/`

Тело:
- `tutor_primary_score` (int)

Права:
- авторизован;
- роль tutor;
- submission принадлежит ученику репетитора (через assignment.tutor или tutor.students).

Ответ:
- `{status: "ok", tutor_primary_score, tutor_scored_at}`

### 2) Перегенерация ИИ репетитором (кулдаун 120 секунд)
`POST /api/tutor/submission/<id>/verify_ai/`

Поведение:
- тот же код, что и у ученика (`api_verify_with_ai`), но с правами репетитора;
- cooldown учитывается по `ai_last_verify_at`.

### 3) Live-обновление списка вариантов у ученика
`GET /api/student/pending-assignments/?subject_id=...`

Ответ:
- JSON со списком (минимально: id, title, due_date, unread replies count) **или** HTML partial.

Рекомендация: начать с JSON (меньше связности с шаблоном).

## Изменения в аналитике

Все места, где сейчас используется `Submission.primary_score` для расчётов (мастерство, прогноз, интервалы и т.п.), должны использовать:
`effective_primary_score` (см. правило приоритета).

Важно: не менять отображение для ученика — там остаётся ИИ.
