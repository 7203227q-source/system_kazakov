# Спецификация: Поддержка нескольких предметов (Multi-Subject Support)

## 1. Обзор (Overview)
Платформа должна поддерживать подготовку учеников к нескольким предметам (например, Физике и Математике) одновременно. Это требует разделения игровых механик (уровни, XP) и целевых баллов, которые сейчас хранятся глобально в модели `User`.
Также необходимо корректно отображать разделение по предметам в дашбордах учеников, репетиторов и родителей.

## 2. Архитектура и База данных (Data Model)

### 2.1. Новая модель: `StudentSubjectProfile`
Создается новая модель для хранения прогресса ученика по конкретному предмету.
*   `student` (ForeignKey к `User`, role='student')
*   `subject` (ForeignKey к `Subject`)
*   `target_score` (IntegerField, default=80) — Целевой балл ученика по этому предмету.
*   `xp` (IntegerField, default=0) — Опыт по предмету.
*   `level` (IntegerField, default=1) — Уровень по предмету.
*   `current_streak` (IntegerField, default=0) — Стрик по предмету.

*Unique constraint*: `unique_together = ('student', 'subject')`

### 2.2. Изменения в модели `User`
*   Поля `target_score`, `xp`, `level`, `current_streak` будут считаться "устаревшими" (deprecated) для глобального использования, но для обратной совместимости во время миграции мы их либо удалим, либо мигрируем данные.
*   *Стратегия миграции*: Напишем Data Migration, которая для каждого ученика с `xp > 0` создаст `StudentSubjectProfile` для предмета "Математика (Профиль)" и перенесет туда `xp`, `level`, `target_score`. После этого поля из `User` можно безопасно удалить.

### 2.3. Изменения в `TutorStudentLink` (или Связях)
Сейчас связь репетитора и ученика реализована через `ManyToManyField` (`tutors`, `parents`). 
Чтобы репетитор мог преподавать конкретный предмет, мы будем использовать фильтрацию по предметам *вариантов* (Assignments), которые репетитор назначает. 
То есть, если репетитор задает вариант по Физике, он видит прогресс ученика по Физике. 

## 3. Пользовательский интерфейс (UI/UX)

### 3.1. Дашборд ученика (`student_dashboard.html`)
*   **Переключатель предметов**: В верхней части экрана добавляется блок вкладок (Tabs) со списком предметов, которые изучает ученик (те, по которым у него есть `StudentSubjectProfile`).
*   **Кнопка "Добавить предмет"**: Позволяет ученику выбрать новый предмет (например, Физику) и задать для него целевой балл.
*   При переключении вкладки обновляются:
    *   Прогресс-бар (Уровень и XP).
    *   Целевой балл.
    *   Список назначенных вариантов (фильтруется по выбранному предмету).

### 3.2. Экран выбора роли (`select_role.html`)
*   При выборе "Я Ученик" система должна просить выбрать **Предмет** (из выпадающего списка) и указать для него **Целевой балл**. Это создаст первый `StudentSubjectProfile`.

### 3.3. Дашборд родителя (`parent_dashboard.html`)
*   В карточке каждого ребенка информация будет сгруппирована по предметам.
*   Вместо одной полоски уровня, родитель будет видеть:
    *   **Математика**: Уровень 5, 80 баллов цель.
    *   **Физика**: Уровень 2, 90 баллов цель.

### 3.4. Дашборд репетитора (`tutor_dashboard.html`)
*   В списке учеников репетитора (и при просмотре детальной статистики) прогресс и уровень будут отображаться с разбивкой по предметам. 
*   Если репетитор сам ведет 2 предмета, он сможет переключаться между ними или видеть сводку.

## 4. Бизнес-логика (Business Logic)

*   **Начисление XP (`views.py: student_solve_assignment`)**:
    При успешном решении задачи определяется её предмет (`task.topic.subject`). XP начисляется в соответствующий `StudentSubjectProfile` ученика.
    Если профиля нет (что маловероятно, но возможно), он создается автоматически с базовыми параметрами.
*   **Проверка черновиков**: Настройка `draft_check_probability` пока остается глобальной (на уровне `User`), так как она отражает уровень доверия репетитора к ученику в целом. Позже её можно будет вынести в связь `TutorStudentLink`.

4. Обновить логику начисления XP в `views.py`.
