## Контекст

Нужно улучшить UX панели репетитора и сделать понятные связи “родитель ↔ ученик”, а также корректно отразить ситуацию, когда ученик занимается по нескольким предметам.

Текущее состояние:
- Внизу `tutor_dashboard` есть табы “Назначить задание / Сообщение ученику / Отчет родителю”, часть — заглушка и/или с внешней отправкой.
- В системе уже есть внутренний чат на модели `Message` и роуты `/chat/...` (`views_chat.py`).
- Связь родитель↔ученик в моделях существует (`User.parents` / `User.children`), но self-service привязки в UI нет.
- У ученика есть предметные профили `StudentSubjectProfile`, переключение предметов у ученика уже реализовано; у репетитора в аналитике уже есть выбор предмета.

## Цели

1) Внизу панели репетитора убрать “Назначить задание”, оставить только отправку сообщений ученику/родителю через внутреннюю систему.
2) Добавить self-service привязку родителя к ученику по инвайт-коду ученика (код на каждого ученика).
3) Для кейса “один ученик — два предмета” оставить одну карточку ученика, но добавить бейджи предметов + быстрый выбор предмета для аналитики.

## Решение

### A) Сообщения в панели репетитора

- В `tutor_dashboard` нижний блок меняем:
  - удаляем вкладку “Назначить задание”;
  - оставляем две вкладки: “Сообщение ученику” и “Сообщение родителю”.
- Внутри вкладок не отправляем “во внешние мессенджеры”.
- Поведение: кнопка “Открыть чат” → редирект в существующий чат:
  - ученику: `/chat/<student_id>/`
  - родителю: `/chat/<parent_id>/` (родитель выбирается из `selected_student.parents`; если несколько — дать select).

Это использует текущие API и хранение сообщений (`Message`), без новых моделей.

### B) Привязка родителя по коду ученика

#### B1) Новый код ученика для родителей

- Добавить в `User` поле `parent_invite_code` (nullable, unique).
- Генерация: при первом обращении в нужных местах (или миграцией) генерируем 6–8 символов (A-Z0-9) с проверкой уникальности.
- Код уникален и привязывает **родителя к конкретному ученику**.

#### B2) UI родителя

- На `parent_dashboard`, если нет привязанных детей, показываем форму:
  - поле “Код ученика”
  - кнопка “Привязать”
- Backend: POST обработчик ищет ученика по `parent_invite_code`, делает:
  - `parent.children.add(student)` и/или `student.parents.add(parent)` (через существующую M2M).

#### B3) Где показывать код

- В панели репетитора (на карточке выбранного ученика) показываем:
  - “Код для родителя: XXXXXXX” + кнопка “Скопировать”.

### C) Ученик с несколькими предметами

В списке учеников (левая колонка) оставляем одну карточку ученика, но:
- выводим бейджи предметов из `student.subject_profiles` (например “Матем”, “Физика”);
- клик по бейджу меняет `subject_id` в query string и обновляет аналитику справа (графики/решаемость/прогноз) для выбранного предмета;
- активный предмет подсвечиваем (если `subject_id` совпадает).

## Ограничения / Безопасность

- Привязку по коду разрешаем только пользователям с `role=parent`.
- Родитель может иметь несколько детей (это уже поддерживает M2M).
- Чат доступен только участникам связи (логика доступа уже есть в `get_user_dialogs`).

## Критерии готовности

- В tutor_dashboard нет таба “Назначить задание”; “Сообщение ученику/родителю” ведёт в чат.
- В parent_dashboard родитель может привязать ученика по коду без Django admin.
- В tutor_dashboard у выбранного ученика отображается parent-код.
- В списке учеников у репетитора видны бейджи предметов и можно быстро переключать аналитику по предмету.
