# Вопросы/комментарии ученика к задаче (ветка по Submission) — дизайн

## Цель

Добавить возможность ученику писать комментарий/вопрос по конкретной задаче в конкретном варианте, чтобы репетитор видел этот вопрос и мог ответить. Комментарии должны быть привязаны к задаче (контекст: вариант + задача), а ученик должен видеть ветку сообщений:

- на странице решения варианта — только после нажатия «Проверить» (когда задача уже проверялась),
- в журнале решений — всегда.

Репетитор должен иметь возможность отвечать:

- в журнале решений репетитора,
- в просмотре варианта репетитором.

## Термины и текущие сущности

- `Assignment` — вариант (репетитор → ученик).
- `Task` — задача.
- `Submission` — решение ученика, уже содержит `student`, `task`, `assignment`, `user_answer`, `is_correct`, и др.

Привязка «ветки общения» делается к `Submission`, так как это уже “единица события” на пересечении `student + assignment + task`.

## Требования

### Функциональные

1. Ученик может отправить сообщение по задаче, даже если ещё не нажимал «Проверить».
2. Репетитор видит сообщения ученика и может отвечать.
3. Ветка сообщений хранит несколько сообщений (чат-ветка).
4. Ветка закрепляется за задачей в рамках варианта (не глобально по задаче).
5. Ученик видит ветку:
   - на странице решения варианта — только после «Проверить»,
   - в журнале решений — всегда.
6. Репетитор отвечает:
   - в `tutor_student_history`,
   - в просмотре варианта репетитором (страница варианта у репетитора).

### Нефункциональные

- Права доступа строго ограничены (ученик — только свои варианты, репетитор — только своих учеников).
- Не ломать текущую механику проверок и сохранения `Submission`.
- Минимально инвазивные изменения интерфейсов: добавляем блоки “вопрос/ответ” без перестройки страниц.

## Модель данных

### Новая модель: `SubmissionComment`

Поля:

- `submission` — FK на `Submission`, `related_name="comments"`, `on_delete=CASCADE`.
- `author` — FK на `User`, `on_delete=CASCADE`.
- `author_role` — `CharField`, значения: `student`, `tutor`.
- `text` — `TextField`.
- `created_at` — `DateTimeField(auto_now_add=True)`.

Индексы/ограничения:

- индекс по `(submission_id, created_at)` для быстрого вывода ветки.

Примечание: отдельное поле `author_role` нужно для упрощённого рендера и дополнительной защиты от “перепутанных” ролей.

## Потоки данных

### Ученик пишет сообщение (до/после проверки)

1. На странице решения варианта ученик вводит текст и отправляет.
2. Бэкенд делает `Submission.get_or_create(student=request.user, assignment=assignment, task=task)`:
   - если `Submission` ещё не было (ученик пишет вопрос “до проверки”), создаётся пустое решение без выставления `is_correct`.
3. Создаётся `SubmissionComment(author=student, author_role="student", text=...)`.
4. UI показывает “Сообщение отправлено”.

### Репетитор отвечает

1. Репетитор открывает журнал решений ученика или просмотр варианта.
2. В нужной задаче видит ветку сообщений и форму ответа.
3. При отправке создаётся `SubmissionComment(author=tutor, author_role="tutor", text=...)`.

## Права доступа

### Ученик

- Создание/чтение комментариев разрешено, если:
  - `submission.student == request.user`,
  - `submission.assignment.student == request.user`.

### Репетитор

- Создание/чтение комментариев разрешено, если:
  - `submission.assignment.tutor == request.user`.

## UI/UX

### Страница решения варианта учеником (`student_solve_assignment`)

Под каждой задачей:

1. Блок “Задать вопрос репетитору” (textarea + кнопка отправки) — доступен всегда.
2. Блок “Вопросы и ответы”:
   - скрыт, если задача ещё не проверялась (`submission.is_correct is None`),
   - показывается после успешной проверки (после нажатия “Проверить”).

Поведение при нескольких сообщениях:

- на странице решения варианта показывать ветку после проверки и сворачивать по умолчанию, если сообщений больше 1 (кнопка “Показать вопросы (N)”).

### Журнал решений ученика (`student_history`)

- Ветка сообщений отображается у каждой записи `Submission` (можно сворачивать по умолчанию, если сообщений > 0).

### Журнал решений репетитора (`tutor_student_history`)

- В раскрывающемся блоке задачи добавить секцию “Вопросы по задаче”:
  - список сообщений,
  - форма ответа репетитора.

### Просмотр варианта репетитором

- В карточке каждой задачи добавить блок “Вопросы по задаче”:
  - список сообщений,
  - форма ответа.

## API/эндпоинты

### Ученик

- `POST /student/assignment/<assignment_id>/task/<task_id>/comment/`
  - создаёт `Submission` при необходимости
  - создаёт `SubmissionComment` от ученика
  - ответ JSON: `ok`, `comment`, `comments_count`

### Репетитор

- `POST /tutor/submission/<submission_id>/comment/`
  - создаёт `SubmissionComment` от репетитора
  - ответ JSON: `ok`, `comment`, `comments_count`

Опционально (для динамической подгрузки без перезагрузки):

- `GET /submission/<submission_id>/comments/` (ученик/репетитор по своим правилам доступа)

## Изменения логики “Проверить”

Существующий endpoint проверки задания в варианте возвращает JSON. Добавить в ответ:

- `comments_count` — количество комментариев по `Submission` после проверки
- `can_view_comments` — `true`, если `submission.is_correct is not None`

UI после успешной проверки:

- показывает кнопку/секцию “Вопросы (N)” и позволяет раскрыть ветку.

## Миграции и обратная совместимость

- Добавление новой таблицы `SubmissionComment` не требует миграции существующих данных.
- Старое поле `Submission.tutor_comment` остаётся неизменным, но в новых интерфейсах не используется как ветка.

## Тестирование

Минимальный набор:

1. Ученик не может написать комментарий к чужому `Submission`.
2. Репетитор не может отвечать на `Submission`, который не принадлежит его варианту.
3. `student_solve_assignment`: ветка скрыта до проверки и доступна после (проверка условий в контексте шаблона/вью).
4. Эндпоинты создания комментариев создают `Submission` при отсутствии (ученик пишет “до проверки”).

## Критерии готовности

- При импорте/решении вариантов (1–5 и любые типы) ученик может написать вопрос по задаче.
- Репетитор видит вопросы и отвечает в журнале и в просмотре варианта.
- На странице решения варианта ученик не видит ветку до нажатия “Проверить”, но видит её после и в журнале.
- Права доступа соблюдены, тесты проходят.
