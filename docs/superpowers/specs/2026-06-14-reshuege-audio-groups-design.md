## Контекст

Текущий импорт с `РешуОГЭ/РешуЕГЭ` сохраняет сами задачи, изображения и текст, но не имеет нормализованного слоя для аудиофайлов.

Из-за этого сейчас не покрываются два важных сценария:

- если у задания есть аудио, оно не импортируется как отдельный переиспользуемый объект;
- если несколько заданий используют один и тот же аудиофайл и относятся к одному общему контексту, система не знает, что это одна логическая группа.

Для английского ОГЭ это критично, потому что блок заданий может быть завязан на одно и то же аудио и должен импортироваться и использоваться как единый контекст.

## Цель

- При импорте с `РешуОГЭ/РешуЕГЭ` скачивать аудиофайл, если он есть у задания.
- Не скачивать аудио повторно, если такой файл уже есть в базе.
- Привязывать несколько заданий к одному и тому же аудио и одному общему контекстному блоку.
- Учитывать эту связку при генерации варианта: если в выбор попало одно задание из группы, в вариант должна попасть вся группа.

## Границы

Изменение делается только для импорта `РешуОГЭ/РешуЕГЭ`.

В этот объём не входят:

- общий media-layer на весь проект;
- поддержка видео и произвольных вложений;
- ручной UI для управления аудиофайлами и группами;
- переработка всех существующих task assets в системе.

## Ключевое решение

Нужен не общий медиа-рефакторинг, а узкий специализированный слой под `РешуОГЭ/РешуЕГЭ`:

- `TaskAudioAsset` — один физический аудиофайл;
- `TaskContextGroup` — один общий контекстный блок задач;
- `Task.context_group` — связь конкретной задачи с контекстной группой.

Один `TaskAudioAsset` может использоваться многими задачами через `TaskContextGroup`.

## Модель данных

### `TaskAudioAsset`

Отдельная модель для скачанного аудио.

Поля:

- `source` — строка-источник, в MVP фиксированно `reshuege`;
- `original_url` — исходный URL аудио;
- `file` — локальный файл в `MEDIA_ROOT`;
- `sha256` — хеш содержимого файла;
- `mime_type` — MIME скачанного файла;
- `size_bytes` — размер;
- `created_at`.

Ограничения:

- уникальность по `(source, original_url)` для быстрого переиспользования уже известного URL;
- уникальность по `(source, sha256)` для дедупликации даже если один и тот же файл доступен по разным URL.

### `TaskContextGroup`

Контекстный блок заданий.

Поля:

- `source` — `reshuege`;
- `group_key` — стабильный ключ группы;
- `audio_asset` — nullable FK на `TaskAudioAsset`;
- `subject` — FK на `Subject`;
- `exam_format` — nullable FK на `ExamFormat`;
- `title` — nullable краткий заголовок группы;
- `position_hint` — nullable позиционный хинт;
- `created_at`.

Ограничения:

- уникальность по `(source, group_key)`.

### `Task`

Добавляется nullable FK:

- `context_group` — FK на `TaskContextGroup`.

Поведение:

- для обычных задач поле пустое;
- для задач, идущих в одном аудио-контексте, все задачи ссылаются на один и тот же `TaskContextGroup`.

## Как определять группу

Предпочтительно использовать явный внешний ключ группы, если он доступен в HTML или структуре страницы.

Если явного ключа нет, fallback для MVP:

- использовать нормализованный `audio_url` как основу `group_key`.

Это допустимо для `РешуОГЭ/РешуЕГЭ`, где один аудиофайл обычно соответствует одному контекстному блоку.

Важно:

- сам `audio_asset` отвечает за переиспользование файла;
- `group_key` отвечает за логическую группу заданий;
- нельзя сводить группу только к `sha256`, потому что один и тот же файл теоретически может встречаться в разных контекстах.

## Поведение импорта

### Шаг 1. Поиск аудио

Во время импорта страницы задачи парсер ищет аудиофайл в HTML.

Если аудио нет:

- задача импортируется как обычно;
- `context_group` не создаётся.

Если аудио найдено:

- URL нормализуется;
- определяется потенциальный `group_key`;
- запускается логика поиска/создания `TaskAudioAsset`;
- запускается логика поиска/создания `TaskContextGroup`.

### Шаг 2. Дедуп по URL

Перед скачиванием система ищет `TaskAudioAsset` по `(source, original_url)`.

Если запись найдена:

- файл повторно не скачивается;
- используется уже существующий asset.

### Шаг 3. Дедуп по содержимому

Если asset по URL не найден:

- файл скачивается;
- считается `sha256`;
- выполняется поиск существующего `TaskAudioAsset` по `(source, sha256)`.

Если совпадение по хешу найдено:

- новый asset не создаётся;
- скачанный временный файл отбрасывается;
- используется уже существующий asset.

Если совпадения по хешу нет:

- создаётся новый `TaskAudioAsset`.

### Шаг 4. Группа

После определения audio asset система ищет `TaskContextGroup` по `(source, group_key)`.

Если группа уже есть:

- новая задача привязывается к существующей группе.

Если группы нет:

- создаётся новая группа;
- в неё записывается `audio_asset`, `subject`, `exam_format` и прочие доступные метаданные.

### Шаг 5. Привязка задачи

Импортированная задача получает ссылку на найденную или созданную `TaskContextGroup`.

В результате все задания одного контекстного блока оказываются в одной группе и используют один и тот же `TaskAudioAsset`.

## Поведение генератора варианта

### Базовый принцип

Если у задачи нет `context_group`, генератор работает как сейчас.

Если у задачи есть `context_group`, эта задача не должна рассматриваться как одиночная единица выбора.

Единица выбора становится вся группа.

### Правила

- если генератор выбрал одну задачу из группы, он обязан включить в вариант все задачи этой группы;
- группа добавляется атомарно;
- если часть группы уже присутствует в наборе, остальные задачи группы дозаполняются без дублей;
- если вся группа не помещается в лимиты варианта, группа пропускается целиком.

### Практический смысл

Для аудио-блоков английского ОГЭ это даёт корректное поведение:

- нельзя включить только одно задание из блока;
- блок сохраняет общий контекст;
- аудио логически соответствует всем заданиям группы.

## Совместимость с текущей логикой bundle

В проекте уже есть `bundle_code`, который используется для логической группировки некоторых задач.

Но для аудио-контекста этого недостаточно, потому что нужно одновременно покрыть:

- отдельный переиспользуемый аудиофайл;
- стабильную связь многих задач с одним общим контекстом;
- поведение генератора варианта.

Поэтому аудио-группы не должны кодироваться только через `bundle_code`.

`TaskContextGroup` — отдельная предметная сущность.

## Ошибки и деградация

Если аудиофайл заявлен, но не скачивается:

- задача всё равно может быть импортирована;
- в лог импорта должна попасть ошибка;
- `TaskContextGroup` может быть создана без `audio_asset`, если контекст группы удалось определить;
- генератор вариантов продолжает учитывать саму группу, даже если аудио физически отсутствует.

Если не удалось определить `group_key`:

- задача импортируется без `context_group`;
- в лог пишется предупреждение;
- система не должна придумывать нестабильные ключи, которые потом разобьют одну группу на несколько.

## MVP

В MVP включаем:

- модель `TaskAudioAsset`;
- модель `TaskContextGroup`;
- поле `Task.context_group`;
- импорт аудио с дедупликацией по URL и `sha256`;
- привязку задач к общей группе;
- поведение генератора варианта с атомарным включением всей группы.

В MVP не включаем:

- общий asset-layer для изображений и других файлов;
- массовую миграцию старых task images на новую модель;
- ручное редактирование групп через UI;
- сложную аналитику по использованию аудио.

## Риски

### Риск 1. Нестабильный `group_key`

Источник может не давать явный идентификатор контекстной группы.

Митигирующее решение:

- использовать явный ключ, если он доступен;
- иначе fallback на нормализованный `audio_url`;
- логировать случаи, где группа не определилась.

### Риск 2. Повторное использование одного файла в разных группах

Один и тот же аудиофайл может теоретически встречаться в нескольких разных контекстах.

Митигирующее решение:

- дедуп файла делать через `TaskAudioAsset`;
- логическую группу определять через `group_key`, а не только через хеш файла.

### Риск 3. Раздувание варианта

Атомарное добавление группы может неожиданно увеличивать количество задач в варианте.

Митигирующее решение:

- проверять bundle целиком до добавления;
- если группа не помещается, пропускать её целиком;
- не разрезать группу частично.

## Критерии готовности

- При импорте с `РешуОГЭ/РешуЕГЭ` аудиофайлы скачиваются и сохраняются как отдельные assets.
- Один и тот же аудиофайл не скачивается повторно, если уже существует в базе.
- Несколько задач могут ссылаться на один и тот же аудио asset через общую `TaskContextGroup`.
- Задачи одного аудио-контекста попадают в одну и ту же группу.
- Генератор варианта при выборе задачи из группы включает всю группу целиком.
- Ближайшая существующая логика импорта и генерации не ломается для задач без аудио.

## Итоговая рекомендация

Оптимальный путь для текущего запроса:

- не строить общий media-layer на весь проект;
- добавить узкий слой `TaskAudioAsset + TaskContextGroup` только для `РешуОГЭ/РешуЕГЭ`;
- дедуплицировать аудио по URL и хешу;
- считать группу атомарной единицей отбора в генераторе вариантов.

Это решает задачу без лишней архитектурной перестройки и покрывает реальную структуру аудио-блоков английского ОГЭ/ЕГЭ.
