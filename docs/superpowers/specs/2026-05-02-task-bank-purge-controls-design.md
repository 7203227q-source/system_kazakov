## Цель

Добавить в «Банк заданий» (страница `tutor_task_bank`) админский блок «Опасная зона» для очистки базы заданий:

- Полная очистка всей базы задач с подтверждением.
- Поэтапное удаление задач по выбранному формату экзамена и/или номеру типа.

Блок должен быть виден и доступен только пользователям с ролью `admin`.

## Контекст

Админ тестирует разные варианты загрузки задач и уникализации и хочет быстро очищать данные:

- Полностью (все задачи).
- Частично (по `ExamFormat` и `TaskType.number`).

## UX / Интерфейс

### Размещение

На странице «Банк заданий» над списком карточек задач, рядом с фильтрами.

### Действия

1) **Удалить задачи по формату экзамена**
- Select: `exam_format_id` (обязательно)
- Поле подтверждения: текстовое поле, в которое нужно ввести `DELETE`
- Кнопка: «Удалить по формату»

2) **Удалить задачи по формату экзамена + номеру типа**
- Select: `exam_format_id` (обязательно)
- Select: `type_number` (обязательно, значения из `TaskType.number` для выбранного формата; либо общий список, если проще)
- Поле подтверждения: `DELETE`
- Кнопка: «Удалить по типу»

3) **Очистить всю базу задач**
- Поле подтверждения: `DELETE ALL`
- Кнопка: «Очистить всю базу»

### Подтверждение

Подтверждение должно быть двухуровневым:

- На фронте: `confirm()` с предупреждением (не как единственная защита).
- На бэке: проверка введённой контрольной фразы.

### Сообщения

После выполнения показывать `messages.success/error` с количеством удалённых задач (и при необходимости вариантов).

## Техническая реализация

### Роутинг

Добавить POST endpoint, например:

- `POST /tutor/tasks/purge/` → `views.tutor_task_purge`

### Доступ

В обработчике:

- Проверять `request.user.role == 'admin'`, иначе `HttpResponseForbidden`.
- Проверять CSRF.

### Логика удаления

#### Общие правила

- Удаляем через ORM (Django), чтобы корректно отработали каскады и M2M.
- Основная сущность для удаления: `Task`.

#### Удаление по exam_format

Выбирать `Task` по связке:

- `Task.task_type.exam_format_id == exam_format_id`

Удалять `Task` queryset.

#### Удаление по exam_format + type_number

Фильтр:

- `Task.task_type.exam_format_id == exam_format_id`
- `Task.task_type.number == type_number`

#### Полная очистка

Удалять все `Task`.

### Побочные удаления (важно)

Удаление `Task` затрагивает:

- `TaskVariant` (FK с `on_delete=CASCADE`)
- `TaskLog`, `TaskGenerationLog`, `SpacedRepetition` (FK с `on_delete=CASCADE`)
- `Submission` (FK с `on_delete=CASCADE`)
- связь `Assignment.tasks` (M2M): должна очиститься автоматически при удалении `Task`

Если окажется, что некоторые связи не каскадятся (например, `on_delete=SET_NULL`), это не блокирует удаление, но нужно проверить консистентность.

## Безопасность

- Только admin.
- Только POST.
- CSRF.
- Подтверждающая фраза обязательна.
- Явные текстовые предупреждения в UI.

## Критерии готовности

- Админ видит «Опасную зону» на `tutor_task_bank`.
- Любая попытка выполнить удаление без правильной фразы отклоняется.
- Удаление по формату и по формату+типу реально удаляет задачи и связанные данные.
- Полная очистка удаляет все задачи.
- Не-админ не видит блок и получает 403 при прямом POST.
