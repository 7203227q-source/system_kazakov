# Стрик занятий по предметам — Design

**Goal:** Сделать рабочий “стрик занятий” **по предметам** (`StudentSubjectProfile.current_streak`), чтобы ученик видел, сколько дней подряд он занимался по текущему (активному) предмету.

**Принятое правило засчёта дня:** “день занятий” засчитывается при **любой попытке** решить задачу по предмету (верно/неверно).

---

## Текущее состояние

- В UI сейчас показывается `user.current_streak`, но в коде отсутствует бизнес-логика обновления стрика (поле по сути “заморожено”).
- В базе уже есть `StudentSubjectProfile.current_streak` (по предмету), но тоже не обновляется.

---

## Предлагаемая реализация

### 1) Модель данных

Добавить поле в `StudentSubjectProfile`:
- `last_streak_date: DateField(null=True, blank=True)`

Это дата, когда стрик по предмету был засчитан последний раз (для идемпотентности “1 раз в день”).

### 2) Правила обновления стрика (идемпотентно)

Функция `touch_subject_streak(student, subject, today)`:
- если `last_streak_date == today`: ничего не делать
- если `last_streak_date == today - 1 день`: `current_streak += 1`
- иначе (пропуск дня или пусто): `current_streak = 1`
- затем `last_streak_date = today`

### 3) Точки вызова (триггеры)

Чтобы правило “любая попытка” работало и в тренажёре, и внутри варианта:

1) **В `record_task_log()`** (центральная точка логирования):
   - после создания `TaskLog` вызвать `touch_subject_streak(student, task.topic.subject, today)`.
   - это покрывает: тренажёр, завершение варианта, verified и т.д.

2) **В `student_check_assignment_task()`** (AJAX проверка одной задачи в варианте):
   - при каждом POST (любая попытка) вызвать `touch_subject_streak(request.user, task.topic.subject, today)`.
   - это важно, потому что `TaskLog` сейчас пишется при `finish`, а стрик должен засчитываться сразу при попытке.

### 4) UI

1) **Дашборд ученика**
- заменить вывод “дней в ударе” с `user.current_streak` на `active_profile.current_streak` (по активному предмету).

2) **Глобальный стрик (совместимость)**
- `User.current_streak` оставить как “глобальный индикатор” для существующих мест UI (например, у репетитора).
- обновлять его как `max(current_streak)` по всем `StudentSubjectProfile` ученика при любом `touch_subject_streak`.

---

## Тестирование

Unit:
- `touch_subject_streak`:
  - первый день → 1
  - второй подряд → 2
  - пропуск дня → 1
  - повторный вызов в тот же день → без изменений

Integration:
- `record_task_log` обновляет стрик по предмету.
- `student_check_assignment_task` обновляет стрик по предмету (без необходимости нажимать “Завершить вариант”).
