# Дизайн: убрать кнопку «Добавить ученика» и сделать рабочим поиск ученика в панели репетитора

Дата: 2026-06-19  
Затрагиваемые страницы: `tutor_dashboard`

## Контекст

В header дашборда репетитора сейчас есть:
- поле `Поиск ученика...`, которое пока не влияет на список;
- кнопка `Добавить ученика`, которая не используется и вводит в заблуждение.

Слева на странице рендерится список учеников репетитора, а выбранный ученик определяется через `GET student_id` и session fallback.

Нужно:
- убрать кнопку `Добавить ученика`;
- сделать рабочим поиск ученика через серверный `GET`-параметр `q`.

## Цели

- Поле поиска должно фильтровать список учеников репетитора по запросу.
- Поиск должен жить в URL, чтобы работать после reload и быть sharable.
- Текущая логика выбора ученика не должна ломаться.
- При отсутствии результатов должен показываться явный empty state.

## Не цели

- Не добавляем live-search/AJAX.
- Не меняем модель привязки ученика к репетитору.
- Не добавляем новый экран/модалку для добавления ученика.
- Не меняем аналитику/правую панель, кроме корректной работы при фильтрации списка слева.

## UX

### Header

- Убираем кнопку `Добавить ученика`.
- Поле поиска превращаем в `<form method="get">`.
- Используем параметр `q`.
- Placeholder остается `Поиск ученика...`.

### Поведение поиска

- Запрос фильтрует только учеников текущего репетитора.
- Поиск выполняется по:
  - `first_name`
  - `last_name`
  - `username`
  - `email`
- Матч — по `icontains`.

### Список слева

- Если `q` пустой — показываем полный список учеников репетитора.
- Если `q` задан — показываем только найденных учеников.
- Если найденных нет — вместо списка показываем текст `Ученики не найдены`.

### Выбранный ученик

- Если текущий `student_id` попадает в отфильтрованный список:
  - сохраняем его выбранным.
- Если не попадает:
  - берем первого ученика из отфильтрованного списка.
- Если результатов нет:
  - `selected_student = None`
  - правая панель остается в безопасном пустом состоянии без 500.

## Технический дизайн

### View: `tutor_dashboard`

Добавляем:

```python
search_query = (request.GET.get("q") or "").strip()
```

Базовый queryset:

```python
students = request.user.students.all()
```

Если `search_query` не пустой:

```python
students = students.filter(
    Q(first_name__icontains=search_query)
    | Q(last_name__icontains=search_query)
    | Q(username__icontains=search_query)
    | Q(email__icontains=search_query)
)
```

Дальше на этот уже отфильтрованный queryset накладываются текущие `prefetch_related(...)` и `annotate(...)`.

В context добавляем:
- `search_query`

### Selection state

После фильтрации:
- если `selected_student_id` найден в `students` — используем его;
- иначе, если `students.exists()` — выбираем первого;
- иначе оставляем `selected_student = None`.

Session fallback сохраняется, но не должен выбирать ученика вне текущего filtered queryset.

### Template: `tutor_dashboard.html`

- header search input оборачивается в форму `GET`;
- из query string сохраняем:
  - `student_id`
  - `subject_id`
  - `range`
  - кроме `q`, который редактируется этим input;
- кнопка `Добавить ученика` удаляется;
- в левой колонке добавляется empty state, если `students` пуст.

### Ссылки в списке учеников

Ссылки вида:

```html
?student_id={{ student.id }}
```

должны сохранять текущие:
- `q`
- `subject_id`
- `range`

чтобы поиск не сбрасывался при переключении ученика.

## Тестирование

Добавить/обновить тесты для `tutor_dashboard`:

1. Кнопка `Добавить ученика` отсутствует в HTML.
2. `q` фильтрует список учеников по имени/username.
3. При активном `q` ссылки на выбор ученика сохраняют query state.
4. При отсутствии результатов страница возвращает `200` и показывает `Ученики не найдены`.
5. Если выбранный ранее ученик не входит в filtered queryset, страница не падает и выбирает первого доступного либо empty state.

## Критерии приемки

- В header больше нет кнопки `Добавить ученика`.
- Поиск по `q` реально фильтрует список учеников репетитора.
- Поиск устойчив к reload и живет в URL.
- Переключение ученика не сбрасывает поисковый запрос.
- При пустом результате интерфейс показывает `Ученики не найдены` без ошибок.
