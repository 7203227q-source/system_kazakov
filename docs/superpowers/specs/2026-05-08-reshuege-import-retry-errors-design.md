## Контекст

При массовом импорте (тысячи задач) часть запросов к sdamgia периодически падает по сети (timeout/502/429 и т.п.). Сейчас UI считает их как `ERR`, но:

- ошибки не сохраняются «на будущее»;
- нет удобного способа повторно импортировать только ошибки.

## Цель

- Не терять список ошибок импорта.
- Дать оператору возможность «докачать» задачи, которые упали с ошибкой, без повторного прогона всего списка.

## Выбранный подход

### Хранение ошибок: localStorage

- Сохраняем список `failed` в `localStorage`, чтобы он переживал перезагрузку страницы в этом браузере.
- Ключ зависит от:
  - `exam_format_id`
  - `type_number`
  - исходного текста в поле `ID/URL задач` (хэш/строка) или нормализованного `view_many` URL
  - `theme` (если есть)

### Кнопка «Повторить ошибки»

- В блоке прогресса показывается кнопка «Повторить ошибки», если для текущего набора параметров есть сохранённые ошибки.
- По нажатию UI прогоняет только ошибочные ID через текущий `step`-эндпоинт:
  - успешные (`ok`) удаляются из списка ошибок,
  - оставшиеся ошибки остаются в localStorage с обновлённой причиной.

### UI-отчёт

- В прогрессе дополнительно показывается:
  - «Ошибок сохранено: N»
  - «Очистить ошибки» (удаляет localStorage-запись для текущего набора)

## Не входит в этот этап

- Авто-ретраи на каждую задачу (оставляем ручной контроль через «Повторить ошибки»).
- Хранение в БД (импорт-сессии) — возможно позже, если понадобится переносимость между устройствами.
