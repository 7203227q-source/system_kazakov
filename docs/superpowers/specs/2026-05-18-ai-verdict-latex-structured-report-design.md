# AI-Вердикт по фото: структурный LaTeX-отчёт и антифрод (design)

## Цель

Сделать ИИ-вердикт по фото решения:

- Прозрачным: сначала показывать, как именно распознано решение ученика, затем ошибки, затем за что сняты баллы, затем итог.
- Устойчивым к “рандомным картинкам”: не начислять баллы за нерелевантное/нечитабельное фото; в таких случаях ставить 0 и давать понятную причину.
- Совместимым с LaTeX: разрешить математику в LaTeX во всех частях отчёта и корректно рендерить на фронте.

## Область

Затрагиваем только проверку по фото для развёрнутой части (эндпоинт `api_verify_with_ai`, UI на странице решения).

## Текущее поведение (как есть)

- Бэкенд просит у модели JSON с полями: `primary_score`, `is_correct`, `recognized_solution`, `mistakes`, `verdict`, `feedback`.
- Если `feedback` пустой, собирается fallback-текст из `recognized_solution/mistakes/verdict`.
- LaTeX-нормализация применяется в основном к `feedback` (`normalize_tex_in_feedback`).
- UI показывает “Вердикт ИИ” из `ai_feedback`, а в деталях (кнопка “Фото и вердикт ИИ”) отдельно выводит `ai_recognized_solution`, `ai_mistakes`, `ai_verdict`.

## Требования (новое поведение)

### Формат: структурный отчёт

Модель должна возвращать JSON, который гарантирует:

- Секцию “Решение (как распознано)” (только то, что реально видно на фото).
- Секцию “Ошибки и замечания”.
- Секцию “Снятие баллов” с разбивкой (критерии, если известны; иначе причины с delta/оценкой) так, чтобы суммарный балл был объясним.
- Секцию “Итоговый вердикт” и обязательную строку “Неуверенность распознавания: …”.

### Антифрод/нерелевантное фото

Если фото:

- не похоже на решение этой задачи,
- содержит другую задачу,
- нечитабельно,
- или модель не уверена в распознавании,

то:

- `primary_score` должен быть 0,
- `is_correct` должен быть `false`,
- отчёт обязан содержать причину и действие “перефотографировать/загрузить корректное фото”.

Порог уверенности по умолчанию: `recognition_confidence < 0.35` ⇒ принудительно 0.

### LaTeX

Разрешить LaTeX-математику (inline `$...$`, block `$$...$$`) в:

- `recognized_solution`,
- каждом элементе `mistakes`,
- каждом элементе `verdict`,
- всех текстовых полях “снятия баллов”.

## Контракт ответа модели (JSON)

Сохраняем существующие поля и добавляем новые (обязательные для новой версии):

- `photo_valid`: boolean
- `photo_valid_reason`: string
- `recognition_confidence`: number (0..1)
- `score_breakdown`: array of objects:
  - `label`: string (например `К1`, `К2`, либо `Ошибка 1`)
  - `awarded`: integer (0..max)
  - `max`: integer (>=0)
  - `reason`: string

Правила:

- `primary_score` должен равняться сумме `score_breakdown[].awarded` (если breakdown непустой).
- `primary_score` ограничивается диапазоном `[0, max_points]`.
- `is_correct = true` только если `primary_score == max_points`.
- Если `photo_valid == false` или `recognition_confidence < 0.35` ⇒ `primary_score = 0`, `score_breakdown` может быть пустым, но причина обязана быть в тексте.

## Бэкенд изменения

### 1) Промпт

В `api_verify_with_ai` расширить промпт требованиями:

- вернуть новые поля (`photo_valid`, `photo_valid_reason`, `recognition_confidence`, `score_breakdown`),
- требовать, чтобы сумма breakdown совпадала с `primary_score`,
- при невалидном фото или низкой уверенности явно ставить 0 и не “додумывать” решение.

### 2) Парсинг и валидация

После `pyjson.loads`:

- нормализовать типы (`recognition_confidence` → float, `photo_valid` → bool),
- применить серверный гейт:
  - если `photo_valid == false` или `recognition_confidence < 0.35` ⇒ принудительно `primary_score=0`, `is_correct=false`,
  - в итоговый отчёт обязательно добавить причину и инструкцию перезагрузки фото (если модель не добавила).
- валидировать `score_breakdown`:
  - привести `awarded/max` к int,
  - отфильтровать мусорные элементы,
  - если сумма awarded не совпадает с `primary_score` — либо исправить `primary_score` на сумму (предпочтительно), либо сбросить breakdown и оставить текстовое объяснение в verdict.

### 3) LaTeX-нормализация

Применить существующую `normalize_tex_in_feedback()` не только к `feedback`, но и к:

- `recognized_solution`,
- каждому элементу `mistakes`,
- каждому элементу `verdict`,
- каждому `score_breakdown[].reason`.

### 4) Хранение

Сохранить breakdown в `Submission`:

- вариант 1: добавить поле `ai_score_breakdown_json` (TextField, JSON-массив объектов),
- вариант 2: временно вложить breakdown в `ai_verdict_json` в отдельной структуре (не рекомендуется из-за смешивания форматов).

Предпочтительно: отдельное поле `ai_score_breakdown_json`.

## UI изменения

### Детальный блок

В “Фото и вердикт ИИ” добавить секцию:

- “Снятие баллов”:
  - выводить список/табличный вид: `label: awarded/max` + `reason`,
  - если `photo_valid == false` или низкая уверенность — подсветить как “нужно перефото”.

### Короткий блок “Вердикт ИИ”

Показывать сводный текст в фиксированном порядке секций:

1) Решение (как распознано)
2) Ошибки и замечания
3) Снятие баллов
4) Итоговый вердикт (включая “Неуверенность распознавания”)

## Совместимость и миграция

- Для старых записей (без breakdown) UI не должен ломаться: секция “Снятие баллов” скрывается.
- После добавления поля `ai_score_breakdown_json` нужна миграция БД.

## Тестирование

- Юнит/интеграционные тесты парсинга JSON:
  - корректный JSON с LaTeX,
  - `photo_valid=false` ⇒ всегда 0,
  - низкая уверенность ⇒ всегда 0,
  - breakdown-сумма не сходится ⇒ исправление/фолбэк.
- E2E/UI проверка:
  - отображение всех секций,
  - LaTeX корректно рендерится в каждой секции,
  - “рандомная картинка” не получает баллы.

## Критерии готовности

- Пользователь всегда видит, что именно распознано и почему выставлен балл.
- Не выдаются “случайные” баллы за нерелевантное/нечитабельное фото.
- LaTeX-математика корректно отображается в распознанном решении, ошибках, снятии баллов и вердикте.
